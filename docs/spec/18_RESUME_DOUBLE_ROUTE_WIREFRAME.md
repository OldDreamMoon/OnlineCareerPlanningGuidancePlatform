# AI 简历优化双路由页面线框说明书

> 文档状态：`evolving`
> 适用范围：学生端 `/ai/resume`
> 配套文档：
> - [`17_RESUME_PAGE_STYLE_GUIDE.md`](docs/spec/17_RESUME_PAGE_STYLE_GUIDE.md)
> - [`14_FRONTEND_ROUTES_AND_PAGES.md`](docs/spec/14_FRONTEND_ROUTES_AND_PAGES.md)
> - [`15_FRONTEND_REFACTOR_CHECKLIST.md`](docs/spec/15_FRONTEND_REFACTOR_CHECKLIST.md)

## 1. 文档目的

本文件不是视觉稿，而是一份给设计 Agent、前端 Agent、UI 生成模型直接使用的“双路由页面线框说明书”。

目标是把 `/ai/resume` 拆成两张职责清晰的页面：

1. `提交操作页`
2. `结果复盘中心`

这样后续无论是继续做高保真设计，还是先做中保真线框，都会更稳定，不会再回到“所有功能堆在一个页面里”的状态。

## 2. 路由拆分建议

### 2.1 推荐路径

- 页面 A：提交操作页
  - 推荐路径：`/ai/resume`
  - 备选路径：`/ai/resume/compose`
- 页面 B：结果复盘中心
  - 推荐路径：`/ai/resume/review`
  - 备选路径：`/ai/resume/results/:recordId`

### 2.2 路由语义

- `/ai/resume` 适合作为默认入口，用户从工作台点击后应先进入这里。
- `/ai/resume/review` 适合作为“分析完成后继续深读、对比、导出、打磨”的主页面。
- 若需要支持从历史直接打开某条结果，可在复盘中心内部附带 `recordId` 查询参数或动态参数。

## 3. 用户主路径

### 3.1 主路径 A：从工作台进入并完成一轮分析

1. 用户从 `/dashboard` 进入 `/ai/resume`
2. 在提交操作页中：
   - 选择目标语境
   - 填写目标岗位
   - 粘贴 JD
   - 上传 PDF 或输入文本
3. 点击开始分析
4. 页面以轻量弹窗 / 内联提示反馈当前进度
5. 分析完成后，给出“进入复盘中心”主按钮
6. 跳转到 `/ai/resume/review`
7. 在复盘中心阅读结果、继续打磨、查看历史、导出 PDF

### 3.2 主路径 B：从历史继续回看

1. 用户进入 `/ai/resume/review`
2. 在历史记录区选择一条历史
3. 切换到对应历史详情
4. 可继续导出或进入改写沙盘

### 3.3 主路径 C：中断后恢复

1. 用户在提交操作页输入到一半离开
2. 再次返回 `/ai/resume`
3. 页面提示检测到本地草稿
4. 用户选择恢复草稿或清空重来

## 4. 页面 A：提交操作页线框

### 4.1 页面定位

这是一张“准备与提交”页面，不是一张结果阅读页。

核心目标：

- 帮助用户快速完成材料准备
- 降低首次使用门槛
- 让分析动作更有仪式感和掌控感
- 在不展示完整结果的前提下，给出足够清楚的轻量反馈

### 4.2 页面结构总览

推荐桌面端线框顺序：

1. 顶栏导航
2. 首屏概览区
3. 主输入工作区
4. 底部操作行与轻量反馈
5. 轻量辅助入口区

### 4.3 区块 1：顶栏导航

位置：

- 页面最顶部，sticky

内容：

- 品牌图标
- 页面标题：`AI Career 简历优化`
- 学生端导航：
  - 工作台
  - 资料中心
  - 技能星图
  - 导师列表
- 右侧操作：
  - 返回工作台
  - 去导师页
  - 当前学生身份信息

线框说明：

- 高度适中
- 半透明白底
- 不承载表单或复杂筛选

### 4.4 区块 2：首屏概览区

建议双栏：

- 左侧：任务定位 Hero
- 右侧：流程说明 / 当前状态摘要

左侧内容：

- 标题
  - 示例：`先准备材料，再拿到更有针对性的简历建议`
- 简短说明
- 三个略大于普通 badge 的状态胶囊：
  - 当前模式
  - 目标语境 / 目标岗位提示
  - 本地草稿状态

右侧内容：

- 三步流程说明：
  - 1. 准备材料
  - 2. 发起分析
  - 3. 进入复盘中心
- 当前额度摘要：
  - 今日剩余
  - 积分余额

线框要求：

- 这里是“定调区”，不是操作重区
- 不放大段输入框
- 不直接显示完整结果
- 三个状态胶囊要比普通 badge 更醒目，但也不要膨胀成大卡片

### 4.5 区块 3：主输入工作区

这是提交操作页的核心。

推荐布局：

- 左侧 `信息与语境区`
- 右侧 `简历输入区`

或在较窄桌面中上下排列：

- 上：信息与语境区
- 下：简历输入区

#### 4.5.1 子区块：目标语境切换

位置：

- 主输入工作区最前部

内容：

- 单层可切换按钮组：
  - 实习投递
  - 校招正式批
  - 社招初阶
  - 技术岗
  - 非技术岗

说明：

- 可允许两种实现：
  - 单选主语境
  - “求职阶段 + 岗位类型”双层轻量组合

线框要求：

- 不能藏得太深
- 应一眼看出当前选中了哪一个

#### 4.5.2 子区块：目标岗位输入

位置：

- 语境切换下方

内容：

- 单行输入框
- 支持 placeholder
- 可有“来自当前资料中心的岗位提示”

线框要求：

- 输入框宽度充足
- 不与其他操作并排过挤

#### 4.5.3 子区块：岗位 JD 对照工作台

位置：

- 主输入工作区核心区域之一

内容：

- JD 文本输入区
- 提示文案：支持粘贴岗位职责、任职要求、加分项
- 一条轻量说明条，提示“这里会作为岗位对照语境使用”

线框要求：

- 这是差异化亮点区
- 不能缩成一条普通文本框
- 但也不能比简历输入区更重
- 当前不再设计单独的“关键词提炼预览卡”

#### 4.5.4 子区块：简历输入模式切换

内容：

- PDF 模式
- 文本模式

线框要求：

- 切换器明确可见
- 切换后下方输入区必须明显变化

#### 4.5.5 子区块：PDF 输入区

内容：

- 拖拽 / 点击上传区域
- 当前文件信息
  - 文件名
  - 文件大小
  - 文件状态
- 移除按钮

线框要求：

- 看起来像文档处理区
- 不是原生 input 的裸包装
- 不假装支持多文件
- 选择文件后，上传区本体必须明显切换到“已准备好”视觉态
- 文件信息应直接嵌入上传框内部，不再拆成上传框下方的单独卡片

#### 4.5.6 子区块：文本输入区

内容：

- 多行文本框
- 可附“使用当前画像提示填充”
- 字数提示可选

线框要求：

- 文字区高度充足
- 适合长文本输入
- 不要让说明文案盖过输入本身

#### 4.5.7 子区块：本地草稿自动保存提示

内容：

- 页面内轻量保存状态：
  - 已自动保存
- 进入页恢复确认弹窗：
  - 检测到本地草稿
  - 已恢复哪些内容
  - 是否需要重新上传 PDF
  - 操作：清空草稿 / 继续编辑

线框要求：

- 页面正文里仅保留轻量保存状态条
- 若存在恢复草稿，允许在进入页使用一层轻量确认弹窗引导用户决定继续或清空

### 4.6 区块 4：底部操作行与轻量反馈

位置：

- 主输入工作区底部

内容：

- 主按钮：`开始分析`
- 次按钮：`清空并重填` 或 `重新开始`
- 提交失败时的轻量错误提示
- 最近结果入口（可选）
- 完成态弹窗：
  - 一句状态结论
  - 进入复盘中心按钮
  - 本轮基础概览

线框要求：

- 不再单独设计整块“提交状态反馈卡”
- 提交操作页只保留轻量反馈，不展开完整报告

### 4.7 区块 5：轻量辅助入口区

建议保留轻量入口，不展开完整功能：

- 查看历史入口
- 去导师页入口
- 返回工作台入口

注意：

- 这些入口是辅助动作
- 不要抢过“开始分析”和“进入复盘中心”

## 5. 页面 B：结果复盘中心线框

### 5.1 页面定位

这是一张“阅读结果、继续打磨、回看历史”的页面。

核心目标：

- 把本次结果讲清楚
- 帮助用户继续改简历
- 让历史记录有复盘价值

### 5.2 页面结构总览

推荐桌面端线框顺序：

1. 顶栏导航
2. 结果概览区
3. 总评与结构化结果区
4. 改写沙盘区
5. 历史记录与历史详情区
6. 长页阅读辅助

### 5.3 区块 1：顶栏导航

内容：

- 与提交页保持同一顶栏体系
- 但在当前页增加：
  - 返回提交页
  - 切换到最近一次结果

### 5.4 区块 2：结果概览区

建议双栏：

- 左：本次结果 Hero
- 右：结构完整度地图

#### 5.4.1 左侧 Hero

内容：

- 标题：本次简历总评
- 目标岗位
- 目标语境
- 一句话总结
- 主 CTA：
  - 导出 PDF
  - 继续改写
- 次 CTA：
  - 去导师页
  - 返回提交页

线框要求：

- Hero 是结果页第一视觉
- 不放太多平级按钮

#### 5.4.2 右侧结构完整度地图

内容：

- 模块列表
  - 基本信息
  - 教育背景
  - 项目经历
  - 实习经历
  - 技能描述
  - 自我介绍
  - 量化成果
  - 岗位匹配表达
- 每项简单评分
- 每项简短提示

线框要求：

- 它是“辅助诊断地图”
- 不是主 KPI
- 不要用巨大雷达图占满区域

### 5.5 区块 3：总评与结构化结果区

推荐顺序：

1. 总评摘要卡
2. 亮点卡组
3. 风险卡组
4. 建议卡组

线框要求：

- 三类卡保持统一结构
- 通过颜色区分语义：
  - 亮点：emerald / teal
  - 风险：amber
  - 建议：indigo
- 支持每条建议的单独操作：
  - 复制
  - 标记稍后处理
  - 打开改写沙盘

### 5.6 区块 4：Before / After 改写沙盘

位置：

- 结构化结果区之后

内容：

- 可按建议项展开
- 每个改写单元包含：
  - 原句
  - 问题说明
  - 推荐改写
  - 我的改写输入区
  - 复制 / 采纳 / 再生成

推荐布局：

- 单条展开式卡片
  或
- 左右双栏：
  - 左：原句 / 问题
  - 右：推荐改写 / 我的改写

线框要求：

- 不一次性展开过多条
- 支持折叠
- 这是“继续打磨区”，不是报告摘要区

### 5.7 区块 5：历史记录与历史详情区

推荐布局：

- 左侧：历史列表
- 右侧：选中详情

内容：

- 历史列表项：
  - 时间
  - 摘要
  - 是否免费 / 消耗积分
- 历史详情：
  - 总评
  - 结构化结果
  - 导出
  - 复制
  - 删除

线框要求：

- 历史区是次级区
- 不要把它放到结果 Hero 之前
- 当前选中项要清晰高亮

### 5.8 区块 6：长页阅读辅助

位置：

- 结果页右侧悬浮区
  或
- 顶部吸顶章节条

内容：

- 当前章节锚点
- 阅读进度
- 返回顶部
- 快速跳转：
  - 总评
  - 亮点
  - 风险
  - 建议
  - 改写沙盘
  - 历史区

线框要求：

- 要轻，不要抢戏
- 优先帮助长页导航，而不是做炫技浮层

## 6. 两个页面之间的衔接规则

### 6.1 从提交页到结果页

必须有明确跳转动作：

- 文案建议：`进入复盘中心`

不建议：

- 提交成功后直接在原页下方硬展开完整结果
- 让用户自己猜下一步去哪

### 6.2 从结果页回到提交页

必须允许：

- 返回修改输入
- 带着当前岗位与语境返回

不建议：

- 回到提交页后丢失全部上下文

### 6.3 从历史进入结果页

必须允许：

- 从历史列表切换当前显示结果
- 结果页始终能清楚告诉用户：
  - 你现在看的是本次结果还是历史结果

## 7. 状态线框要求

### 7.1 提交操作页状态

- 初始空态
- 已恢复草稿态
- 提交中态
- 完成态
- 失败态

### 7.2 结果复盘中心状态

- 正在生成中
- 结果可读态
- 历史为空态
- 历史详情加载态
- 导出反馈态

## 8. 线框标注规范

后续让其他 AI 出线框时，建议强制要求它在每个区块下标注：

- 区块名称
- 区块目的
- 主要内容
- 主要操作
- 与其他区块的关系

这样比只出一张大布局图更容易落地。

## 9. 给其他 AI 的线框任务提示词

下面这段可以直接给其他 AI，用于生成“双路由页面线框方案”：

```text
请为学生端 AI 简历优化功能设计“双路由桌面端线框”。

页面拆分：
1. 提交操作页：负责目标语境、目标岗位、JD 对照、PDF/文本输入、本地草稿自动保存、发起分析、以轻量弹窗/内联提示反馈基础状态
2. 结果复盘中心：负责总评、亮点/风险/建议、结构完整度地图、Before/After 改写沙盘、历史记录与历史详情、导出 PDF、长页阅读辅助

真实约束：
- 页面属于学生工作台体系
- 顶栏和容器宽度与学生工作台统一
- 不要做深色赛博风
- 不要把评分设计成权威 ATS 分
- 提交页不再暴露输出语言选择
- JD 对照区不再包含关键词提炼预览卡
- 提交页不再单独做大块状态反馈卡
- 提交操作页不能直接展开完整结果
- 历史区只属于结果复盘中心
- 本地草稿自动保存只做当前草稿恢复，不做多快照版本时间线

请输出：
1. 两个页面的整体信息架构
2. 每个页面的区块清单
3. 每个区块的线框说明
4. 两个页面之间的跳转关系
5. 哪些区块应该主视觉突出，哪些只能做辅助
```
