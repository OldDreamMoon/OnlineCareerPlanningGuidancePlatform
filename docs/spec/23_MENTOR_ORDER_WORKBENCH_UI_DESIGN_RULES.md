# 导师订单中心（订单工作台）UI 设计规则

> 文档状态：`evolving`
> 最近同步：2026-04-08
> 适用范围：导师端 `/mentor/orders`
> 用途：以当前真实前后端实现为准，定义导师订单中心的职责边界、页面结构与验收口径。

## 1. 页面定位

`/mentor/orders` 当前已经是导师处理咨询订单的主工作台。

它负责：

- 全局搜索与多维筛选
- 优先级判断
- 总览卡片
- 列表分页
- 详情快照弹窗
- 把导师送入单笔履约工作区

它不负责：

- 完整消息线程
- 完整学生档案长页
- 财务中心口径

一句话：

`订单中心负责找单、筛单、判断优先级，不负责把单笔履约做完。`

## 2. 当前真实实现（2026-04-08）

- 页面当前已正式接入 `GET /api/v1/consult/orders/mentor-workbench`
- 页面不再依赖旧的 `/consult/orders` 基础列表做前端本地拼装
- 当前采用“旧快照先渲染 + 后台静默刷新”的工作台模式
- 页面已经真实支持：
  - 关键词搜索
  - 状态筛选
  - 服务方式筛选
  - 时间筛选
  - 支付方式筛选
  - 风险筛选
  - 排序
  - 服务端分页
  - 详情弹窗
  - 进入履约区
- 当前已支持 `orderNo` 深链接选中和详情补拉，便于从通知中心或财务中心回流后直接打开快照

## 3. 当前真实后端契约

### 3.1 `GET /api/v1/consult/orders/mentor-workbench`

当前真实支持参数：

- `page`
- `size`
- `keyword`
- `status`
- `serviceFilter`
- `timeFilter`
- `paymentMode`
- `riskFilter`
- `sortMode`

当前真实返回：

- `summary`
- `records`
- `total`
- `page`
- `size`
- `availablePaymentModes`

### 3.2 摘要返回

当前顶部摘要卡已由服务端直接聚合：

- `pendingReplyCount`
- `expiringSoonCount`
- `waitingConfirmationCount`
- `afterSalesImpactCount`

### 3.3 列表项返回

当前列表项已包含：

- `orderNo`
- 学生侧展示名
- 金额
- 状态
- 问题摘要
- 支付方式
- 预约时间
- 创建 / 支付 / 关闭时间
- `mentorReplyDeadlineAt`
- 售后影响标记

因此，旧文档中“后端缺少复杂筛选与工作台聚合”的说法已经失效。

## 4. 页面职责边界

### 4.1 订单中心负责什么

- 订单分诊摘要
- 全局筛选
- 风险识别
- 列表浏览
- 详情快照
- 跳转履约区

### 4.2 订单中心不负责什么

- 展开完整沟通记录
- 发送正式回复
- 处理提现
- 编辑导师资料

## 5. 当前页面结构

### 5.1 顶部区

当前顶部区负责：

- 页面标题与说明
- 返回工作台
- 去财务中心
- 刷新

### 5.2 摘要卡区

当前摘要卡用于快速判断：

- 待回复订单
- 即将超时
- 已回复待确认
- 售后 / 退款影响

### 5.3 搜索与筛选区

这是页面当前的正式核心区。

要求保留：

- 关键词
- 状态
- 服务方式
- 时间
- 支付方式
- 风险
- 排序

### 5.4 列表区

当前列表每项至少展示：

- 订单号
- 学生昵称
- 金额
- 问题摘要
- 关键时间
- 状态与风险标记
- 两个动作：
  - `查看快照`
  - `进入履约区`

### 5.5 详情快照弹窗

当前弹窗已经收口为轻量快照，不再使用复杂 Hero 式头部。

当前结构应保持：

- 简洁顶部状态栏
- 基础订单信息
- 咨询问题摘要
- 学生背景摘要
- 订单来源与服务信息
- 材料摘要
- 评价反馈
- 售后摘要
- 进入履约区动作

弹窗的职责仍然是“快速判断要不要进履约区”，不是把所有资料都塞进弹窗。

## 6. 当前实现规则

- 订单中心必须继续以服务端聚合查询为权威来源，不再退回本地全量聚合
- 页面应保留旧快照缓存与静默刷新策略，不在前台显式提示“正在使用缓存”
- 快照弹窗中可以展示学生背景与材料摘要，但应只保留分诊所需信息，不与履约区重复堆叠
- 从本页进入单笔订单后，完整处理统一交给 `/mentor/orders/:orderNo/workspace`

## 7. 当前不再成立的旧口径

以下描述已经失效：

- “订单中心后端只支持基础分页与 `status` 过滤”
- “关键词搜索 / 风险筛选 / 排序仍未正式落地”
- “订单中心仍需新增专门详情页”

## 8. 验收关注点

- `/mentor/orders` 打开后应优先显示旧快照，并在后台完成静默刷新
- 各筛选项和排序应真实走服务端聚合接口
- `availablePaymentModes` 应真实来自接口返回，不应前端硬编码
- 详情弹窗应能从列表、通知回流和 `orderNo` 查询串稳定打开
- “进入履约区”应稳定跳转 `/mentor/orders/:orderNo/workspace`
