# 导师广场 UI / 需求设计规则

> 文档状态：`frozen`
> 当前定稿：2026-03-26
> 适用范围：学生端 `/mentors`
> 用途：为后续 UI / 前端 / 后端 Agent 提供统一的正式需求基线，同时为毕设论文中的“AI 推荐式导师匹配”能力提供稳定的产品口径。

## 1. 文档目标

本文件不是接口文档，也不是逐像素视觉稿。

它的目标是：

- 明确学生端 `/mentors` 的正式页面定位，不再停留在“简历页之后的临时跳转页”
- 直接确定本页最终实际功能范围，不再拆分“基础版 / 增强版 / 概念版”
- 把“AI 属性”正式收口到可解释、可落地、可用于论文叙述的导师推荐系统
- 约束后续 UI、前端、后端围绕同一套页面职责推进，避免导师广场、导师详情、咨询创建页互相抢职责

一句话总结：

`导师广场应该被设计成“学生发现导师、获得 AI 推荐、完成咨询准备并进入下单前决策”的主入口页。`

## 2. 上位约束来源

以下约束来自当前项目中的上位文档与真实页面边界：

- `docs/spec/01_PRD.md`
  - 导师相关 P1 能力包括“异步 1v1 导师付费咨询”
  - 项目整体应体现“AI + 成长体系 + 导师”的融合模式
- `docs/spec/14_FRONTEND_ROUTES_AND_PAGES.md`
  - `/mentors` 属于学生路由中的导师浏览入口
  - `/mentors/:mentorUserId` 当前保留为兼容深链接与未来扩展位，正式详情承接仍以 `/mentors` 当前 master-detail 设计为准
  - `/consult/create` 继续承担独立下单职责
- `docs/spec/19_MENTOR_DASHBOARD_UI_DESIGN_RULES.md`
  - 导师工作台负责导师侧分诊与经营摘要，不负责学生侧曝光与筛选
- `docs/spec/20_MENTOR_PROFILE_UI_DESIGN_RULES.md`
  - 导师资料页负责公开服务名片的编辑、预览、认证与排期配置
  - 导师头像、轻量封面、公开展示控制、多场景预览已纳入正式范围
- `apps/web/src/pages/MentorSelectionPage.tsx`
  - 当前学生端已存在 `/mentors` 的最小联调页，说明本页已具备真实路由入口，但仍处于占位式能力

## 3. 页面定位

`/mentors` 的正式定位不是：

- 仅服务简历页跳转的附属页面
- 导师详情页的压缩替代物
- 订单创建页
- 社区内容聚合页
- 排班预约页

它的正式定位是：

- 学生端“导师发现与筛选”的主入口
- 基于问题场景与 AI 推荐的导师广场
- 学生完成“浏览、收藏、初步判断、咨询准备”的决策页

一句话：

`导师广场首先要回答“现在谁更适合帮我解决问题”，而不是“如何立刻支付”。`

## 4. 页面职责边界

### 4.1 导师广场负责什么

- 读取学生上下文并生成 AI 推荐结果
- 提供问题场景驱动的导师筛选
- 展示导师卡片列表
- 提供右侧快速预览，帮助学生完成第一轮判断
- 支持收藏导师
- 支持生成咨询准备单
- 把学生平滑送入后续咨询创建页

### 4.2 导师广场不负责什么

- 不承载导师完整详情长页
- 不承载完整下单与支付流程
- 不承载即时聊天
- 不承载复杂导师对比系统
- 不承载复杂排班可视化
- 不承载社区内容运营页

### 4.3 与其他页面的职责拆分

- `/mentors`
  - 负责发现、筛选、推荐、收藏、咨询准备，以及当前正式的导师详情快速预览工作区
- `/mentors/:mentorUserId`
  - 当前只作为兼容深链接入口，把目标导师收口到 `/mentors?mentor=...` 的选中态
  - 后续若建设独立导师长页，再承接更长的公开资料、更多评价与更完整的排期浏览
- `/consult/create`
  - 负责正式创建咨询订单，不回流承担推荐与导师发现职责
  - 当前正式设计已独立沉淀到 `docs/spec/25_STUDENT_CONSULT_ORDER_CREATE_UI_DESIGN_RULES.md`
- `/mentor/profile`
  - 负责导师编辑自己的公开名片，不承担学生端的推荐与选择逻辑

### 4.4 当前实现补充（2026-03-26）

- 用户已明确裁决：当前学生侧不再新增独立的导师详情长页。
- 前端正式实现继续采用 `/mentors` 页内 master-detail 结构：
  - 左侧列表负责发现、筛选、收藏与选择
  - 右侧快速预览负责当前正式的“导师详情”体验
- `/mentors/:mentorUserId` 已作为兼容深链接路由落地，用于通知、收藏或外部跳转稳定命中当前选中的导师，而不是分叉出第二套页面设计。

## 5. 正式功能范围

本文件不再对本页做“基础功能 / 增强功能 / 概念功能”分层。

以下 5 项均为本页最终正式功能：

1. AI 智能推荐系统
2. 问题场景筛选
3. 导师广场列表与右侧快速预览
4. 咨询准备单
5. 收藏功能

本轮明确不纳入范围的能力见第 13 章。

## 6. 页面信息架构

页面正式采用宽屏桌面端四段结构：

1. 页面头部
2. AI 推荐与筛选区
3. 左侧导师列表区
4. 右侧导师快速预览区

### 6.1 页面头部

页面头部必须包含：

- 页面标题：`导师广场`
- 副标题：强调“按问题、方向和推荐理由找导师”
- 来源提示条
- 返回工作台入口
- 返回 AI 简历页入口
- 收藏数量入口

### 6.2 来源提示条规则

来源提示条只影响文案，不改变页面主体结构。

推荐规则：

- 从工作台进入：展示通用提示
- 从简历页进入：提示“建议带着简历问题来找导师”
- 从面试页进入：提示“建议带着复盘问题来找导师”
- 无来源信息：展示默认提示

## 7. AI 智能推荐系统

这是本页最核心的正式功能。

### 7.1 推荐系统定位

推荐系统采用：

- `规则加权排序` 作为核心机制
- `AI 生成解释文案` 作为辅助层
- `可解释、可复现、可控` 作为基本原则

本页不采用纯黑盒大模型直接产出最终榜单。

### 7.2 推荐系统目标

推荐系统要解决的不是“随机推 3 位导师”，而是：

- 基于学生当前问题与求职上下文给出更合理的候选人
- 明确告诉学生“为什么推荐这些导师”
- 把 AI 简历、AI 面试与导师咨询三条主链路连接起来
- 为论文中的 AI 应用部分提供稳定、可叙述的产品设计

### 7.3 推荐系统输入源

推荐系统正式使用以下输入源，优先级从高到低如下：

1. 学生当前在本页选择的问题场景
2. 学生资料中的目标岗位、技能标签、自我介绍
3. 最近一次 AI 简历诊断结果
4. 最近一次 AI 模拟面试总结结果
5. 当前筛选条件中的关键词、价格、可接单条件

说明：

- 问题场景是最高优先级输入
- 当学生缺少简历或面试记录时，系统仍可退化到“场景驱动 + 资料驱动 + 公共列表”推荐

### 7.4 推荐系统输出结果

推荐系统固定输出：

- Top 3 推荐导师
- 每位导师的匹配分 `0-100`
- 2 到 3 条推荐理由标签
- 1 条风险或注意提示
- 一段简短的推荐解释文本

推荐理由示例：

- `匹配你的简历诊断需求`
- `擅长前端项目表达`
- `与你的目标岗位高度相关`
- `当前可接单`
- `评价稳定`

风险提示示例：

- `当前暂不可接单`
- `公开评价样本较少`
- `价格高于当前偏好`

### 7.5 推荐系统打分维度

推荐分正式采用 100 分制，固定由以下 6 个维度组成：

- 问题场景匹配度：35 分
- 能力短板 / AI 诊断问题匹配度：25 分
- 目标岗位 / 擅长方向匹配度：20 分
- 导师质量信号：10 分
- 可接单状态：5 分
- 价格适配度：5 分

解释如下：

- 问题场景匹配度
  - 学生当前问题场景与导师服务场景的匹配程度，是最高权重
- 能力短板 / AI 诊断问题匹配度
  - 学生最近一次简历优化和面试总结暴露的问题，与导师标签、服务场景、简介关键词之间的匹配程度
- 目标岗位 / 擅长方向匹配度
  - 学生目标岗位、技能标签与导师擅长方向的相关度
- 导师质量信号
  - 使用公开可信信号，例如评分与历史咨询量
- 可接单状态
  - 当前可接单导师获得明确加分，但不是唯一硬门槛
- 价格适配度
  - 只有在用户设置了价格偏好时，才产生明显影响

### 7.6 推荐系统规则

推荐系统正式规则如下：

- 默认展示 Top 3 推荐导师
- 问题场景切换后，推荐结果必须实时重算
- 关键词和价格筛选会影响候选集合，但不替代推荐逻辑
- 收藏状态本轮不参与推荐打分
- 推荐理由必须对应真实命中的打分维度
- 当学生资料不足时，页面必须明确提示“当前推荐依据较弱”

### 7.7 推荐区界面表现

推荐区固定放在导师列表上方，包含：

- `AI 为你推荐` 主标题
- 3 张推荐导师卡
- 一条推荐依据说明
- 一个“重新推荐”按钮

“重新推荐”不是随机洗牌，而是基于新的场景与筛选条件重新计算。

推荐依据说明必须清楚表达本次推荐使用了哪些输入源，例如：

- 基于你的目标岗位、最近简历诊断结果和当前问题场景推荐
- 当前缺少面试记录，本次未纳入面试表现因素

## 8. 问题场景筛选

问题场景筛选是本页正式主筛选器，也是推荐系统最高优先级输入。

### 8.1 交互规则

- 只支持单选主场景，不做多选
- 选中问题场景后，同时刷新推荐结果和导师列表
- 场景筛选状态必须保留到 URL query
- 从简历页或面试页带入场景参数时，页面首次进入自动选中对应场景
- 问题场景优先级高于普通关键词

### 8.2 固定场景集合

正式固定为以下 7 类：

- `简历诊断`
- `项目表达`
- `模拟面试复盘`
- `岗位方向选择`
- `校招投递策略`
- `转行 / 跨专业求职`
- `Offer 对比与决策`

并保留默认项：

- `不限`

## 9. 导师广场列表

导师列表区承担“发现、筛选、形成第一轮候选集”的职责。

### 9.1 正式支持的筛选项

- 搜索关键词
- 问题场景单选
- 价格筛选
- 仅看可接单
- 仅看收藏
- 重置筛选
- 结果数显示
- 分页
- 当前筛选状态 URL 保留

本轮不做排序器，页面统一保持后端默认推荐顺序。

### 9.2 导师卡片字段

每张导师卡片正式展示以下信息：

- 导师头像
- 导师显示名
- 公司名称
- 职位名称
- 擅长方向标签
- 问题场景标签
- 咨询价格
- 评分
- 当前可接单状态
- 收藏按钮
- 若命中推荐结果，显示 `AI 推荐` 标识
- 一条简短推荐理由摘要

### 9.3 导师卡片主操作

卡片主操作固定为：

- 选中并在右侧预览
- 收藏 / 取消收藏

本页不在卡片上直接承担完整下单动作。

### 9.4 无结果态要求

无结果时，页面不能只显示“没有数据”，而必须给出恢复建议。

至少支持以下建议动作：

- 放宽价格区间
- 取消“仅看可接单”
- 切换到更通用的问题场景
- 取消“仅看收藏”

## 10. 右侧导师快速预览

右侧区域只做“快速预览”，不替代完整详情长页。

### 10.1 快速预览区字段

右侧快速预览正式包含：

- 头像与轻量头图
- 导师姓名
- 公司与职位
- 擅长方向标签
- 问题场景标签
- 咨询价格
- 评分
- 历史咨询量
- 当前可接单状态
- 导师简介
- 最近 3 条评价
- 当前推荐理由标签
- 收藏按钮
- `生成咨询准备单` 主按钮

### 10.2 快速预览区职责

右侧区域的目标是帮助学生完成第一轮判断：

- 这个导师大概适不适合我
- 为什么系统会推荐他
- 我是否要先收藏
- 我是否要开始准备咨询问题

本区不承载完整长页内容，不承载正式下单表单。

## 11. 咨询准备单

咨询准备单是本页正式功能，不是可有可无的附属弹窗。

### 11.1 功能定位

咨询准备单用于：

- 帮学生把模糊想法整理成可真正发起咨询的问题
- 降低咨询前的表达门槛
- 承接导师广场到咨询创建页的过渡

### 11.2 打开方式

咨询准备单通过按钮打开，形式采用抽屉或 Modal，不新增独立路由。

### 11.3 固定结构

咨询准备单正式包含以下字段：

- 已选导师信息
- 当前问题场景
- 目标岗位
- 当前困扰摘要
- 三个核心咨询问题
- 已准备材料清单
- 希望获得的结果

字段说明：

- 已选导师信息
  - 只读，显示当前选中的导师基础信息
- 当前问题场景
  - 默认继承当前页已选场景，可手动调整
- 目标岗位
  - 默认从学生资料带入，可手动修改
- 当前困扰摘要
  - 一段 100 到 300 字的文字，用于描述当前问题
- 三个核心咨询问题
  - 固定为 3 条，允许用户编辑
- 已准备材料清单
  - 固定选项：`简历`、`岗位 JD`、`面试复盘结果`、`项目介绍`、`其他补充材料`
- 希望获得的结果
  - 固定选项：`获得简历修改建议`、`获得面试复盘建议`、`获得求职方向建议`、`获得综合咨询建议`

### 11.4 咨询准备单的 AI 能力

咨询准备单明确支持 `AI 一键生成草稿`。

AI 生成时可读取：

- 学生资料
- 最近一次简历优化结果
- 最近一次面试总结结果
- 当前问题场景
- 当前导师擅长方向

AI 生成内容包括：

- 当前困扰摘要
- 三个核心咨询问题
- 建议准备材料

用户必须可以：

- 手动修改
- 重新生成
- 清空重写

### 11.5 草稿保存与流转规则

本页正式要求：

- 咨询准备单草稿按“学生 + 导师 + 场景”维度本地保存
- 页面刷新后可恢复最近草稿
- 点击“带着准备单去咨询”后，跳转到 `/consult/create`
- 准备单内容自动转成咨询创建页的默认提问文本、结构化预填字段与初始材料建议

本轮不建设独立的服务端准备单草稿中心。

## 12. 收藏功能

收藏功能正式纳入本页。

### 12.1 功能定位

收藏用于：

- 帮学生形成短期候选池
- 支持学生在多位导师之间做延迟决策
- 让学生可以稍后回到导师广场继续判断

### 12.2 正式功能点

- 导师卡片可收藏 / 取消收藏
- 右侧预览区可收藏 / 取消收藏
- 顶部显示当前收藏数量
- 支持 `仅看收藏`
- 收藏状态跨登录保留
- 收藏状态在列表和预览区实时同步

### 12.3 明确不纳入的收藏能力

- 不做分组收藏夹
- 不做收藏备注
- 不做分享
- 不做收藏导师对比

### 12.4 持久化原则

收藏必须服务端持久化，不采用纯 `localStorage` 方案。

## 13. 本页明确不纳入范围的功能

以下能力本轮明确不做：

- 导师对比模式
- 最近浏览
- 导师专题运营区
- 导师社区内容预览
- 服务包体系
- 即时聊天
- 复杂排序器
- 复杂预约排班可视化
- 直接在本页支付
- 收藏夹分组与备注

## 14. 为实现正式功能需补齐的公开导师字段与接口能力

本文件不是 API 文档，但为了让正式功能闭环，以下契约被视为本页实现的正式依赖。

### 14.1 导师公开字段

导师公开数据至少需要补齐：

- `avatar`
- `companyName`
- `jobTitle`
- `serviceScenes`

说明：

- `avatar` 用于卡片与右侧预览的真实头像展示
- `companyName`、`jobTitle` 用于增强信任感与匹配判断
- `serviceScenes` 是问题场景筛选和推荐系统的核心数据来源

### 14.2 推荐系统能力

建议新增能力：

- `GET /mentors/recommendations`

至少应返回：

- 推荐导师列表
- 匹配分
- 推荐理由
- 风险提示
- 本次推荐依据说明

### 14.3 收藏能力

建议新增能力：

- `POST /mentors/{mentorUserId}/favorite`
- `DELETE /mentors/{mentorUserId}/favorite`
- `GET /mentors/favorites`

### 14.4 咨询准备单 AI 生成能力

建议新增能力：

- `POST /mentors/prep-sheet/generate`

至少应返回：

- 当前困扰摘要草稿
- 三个核心咨询问题草稿
- 建议准备材料

## 15. 页面主链路

本页正式主链路固定为：

1. 学生进入导师广场
2. 页面读取来源与学生上下文
3. 系统生成 Top 3 推荐导师
4. 学生选择问题场景或调整筛选条件
5. 推荐区和列表区同步刷新
6. 学生浏览列表并收藏候选导师
7. 学生点击某位导师，在右侧查看快速预览
8. 学生点击“生成咨询准备单”
9. AI 帮学生生成咨询草稿
10. 学生手动修改
11. 学生点击“带着准备单去咨询”
12. 页面跳转到 `/consult/create`，继续完成咨询创建

## 16. 验收标准

本页正式验收标准如下：

1. 学生进入页面后，能看到 AI 推荐结果，或看到明确的推荐降级提示。
2. 问题场景切换后，推荐区和列表区会同步更新。
3. 页面支持关键词、场景、价格、可接单、收藏 5 类筛选。
4. 每位导师卡片至少展示头像、姓名、公司职位、标签、价格、评分、接单状态、收藏按钮。
5. 右侧预览区可帮助学生完成第一轮判断，而不必立刻跳转到其他页面。
6. 咨询准备单支持 AI 自动生成草稿，并允许手动修改。
7. 咨询准备单内容可带入后续咨询创建页。
8. 收藏状态跨登录保留，并支持仅看收藏。
9. 全页具备完整的加载态、错误态、无结果态、空收藏态。
10. 宽屏桌面端结构稳定、信息层次清楚，适合作为答辩演示页面。
