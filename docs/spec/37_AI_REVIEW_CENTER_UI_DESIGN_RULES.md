# AI 复盘中心 UI / 需求设计规则

> 文档状态：`evolving`
> 当前版本：2026-03-26
> 适用范围：学生端 `/ai/history`
> 用途：为后续 UI / 模板 / 前端 Agent 提供统一设计基线；本轮只定义正式页面定位与信息架构，不直接落地页面代码。

## 1. 文档目标

本文件不是接口文档，也不是单纯的页面脑图。

它的目标是：

- 明确 `/ai/history` 不再是普通“历史列表页”，而是学生端独立的 `AI 复盘中心`
- 把“简历修改复盘”和“模拟面试复盘”统一收口到同一个宽屏工作区
- 为其他 AI 生成页面模板时提供足够明确的模块边界、桌面端布局与交互优先级
- 约束后续实现必须贴合当前真实后端能力，不额外假设新接口

一句话总结：

`AI 复盘中心应该像一个学生的个人复盘工作台，而不是按时间堆叠的历史流水页。`

## 2. 页面定位

`/ai/history` 的正式定位不是：

- 一个只有时间、标题、删除按钮的朴素历史列表
- 只给技术联调用的调试页
- AI 简历页或 AI 面试页的附属弹窗
- 独立的第三条 AI 工具主链路

它的正式定位是：

- 学生端统一回看 AI 结果的复盘工作台
- 简历优化与模拟面试两条 AI 能力的历史资产中心
- 学生决定“继续修改简历、再次练习、去找导师”的中转枢纽

一句话：

`AI 复盘中心首先要回答“我过去做了什么、现在最值得继续处理哪一条”，而不是“我一共调用了多少次 AI”。`

## 3. 路由与导航语义

### 3.1 正式路由

- 主路由：`/ai/history`

### 3.2 推荐的选中态 query 方案

为方便后续通知回流、列表选中与刷新后保持上下文，推荐使用：

- `?type=resume&recordId={recordId}`
- `?type=interview&sessionId={sessionId}`

说明：

- `type` 只允许 `resume` 或 `interview`
- 未携带 query 时，默认选中当前列表第一条记录
- query 无效、记录不存在或已删除时，应优雅回退到当前列表首项或空态，不允许进入死链

### 3.3 页面入口与回流

本页应允许从以下位置进入：

- 学生工作台中的 AI 能力区
- AI 简历页 `/ai/resume`
- AI 模拟面试页 `/ai/interview`
- 统一通知中心 `/notifications`

本页应提供以下回流 CTA：

- 去 `/ai/resume`
- 去 `/ai/interview`
- 去 `/mentors`

## 4. 上位约束与真实后端边界

### 4.1 上位约束

- `docs/spec/14_FRONTEND_ROUTES_AND_PAGES.md`
  - `/ai/history` 已被保留为学生端正式规划路由
  - 当前页面定位已从“AI 历史”升级为“AI 复盘中心（规划）”
- `docs/spec/15_FRONTEND_REFACTOR_CHECKLIST.md`
  - 本页正式职责已被提升为独立页面专项，而不是普通补页
- `apps/server-java/src/main/java/com/bishe/server/api/AiController.java`
  - 当前真实接口以历史列表、单条详情、删除为核心

### 4.2 当前真实后端能力

本轮模板与前端设计必须以以下真实接口为边界：

- `GET /api/v1/ai/history`
  - 历史分页列表
  - 支持 `page`、`size`、`taskType`
- `GET /api/v1/ai/history/resume/{recordId}`
  - 简历复盘详情
- `DELETE /api/v1/ai/history/resume/{recordId}`
  - 删除简历复盘记录
- `GET /api/v1/ai/interview/sessions/{sessionId}`
  - 模拟面试会话详情
- `DELETE /api/v1/ai/interview/sessions/{sessionId}`
  - 删除模拟面试记录

当前代码还存在一个可用但非本页主阻塞的附加能力：

- `GET /api/v1/ai/resume/export/{recordId}`
  - 服务端文件流版简历 PDF 导出

当前学生端页面的主链路导出方式已经调整为：

- 基于 `GET /api/v1/ai/history/resume/{recordId}` 返回的结构化详情
- 在浏览器侧使用标准 PDF 渲染方案生成下载文件
- 不再依赖旧的打印预览式导出体验

### 4.3 当前列表接口可用字段

`GET /ai/history` 当前返回的单条列表记录字段为：

- `id`
- `taskType`
  - 当前真实值以 `RESUME`、`INTERVIEW_TEXT` 为主
- `summary`
- `pointsConsumed`
- `sessionId`
  - 仅面试记录有值
- `status`
  - 当前用于面试会话状态回看
- `createdAt`

这意味着本页的主筛选与展示必须贴合真实字段，不应强依赖后端暂未提供的复杂标签、评分区间、关键词统计等能力。

## 5. 页面核心目标

本页必须同时满足 4 个目标：

1. 让学生可以快速区分“简历复盘”和“模拟面试复盘”两类历史。
2. 让学生进入任意一条历史后，不需要跳到其他页面就能完成主要回看动作。
3. 让学生在回看后顺滑进入“继续修改简历 / 再练一轮面试 / 去找导师”的下一步。
4. 在宽屏桌面端下形成明显的“历史导航 + 详情工作区”结构，而不是把所有内容纵向堆叠。

## 6. 正式信息架构

页面正式采用 `顶部概览 + 主工作区` 的两层结构。

### 6.1 顶部概览层

顶部概览层负责告诉学生：

- 这里是什么页面
- 当前总共有多少条可复盘记录
- 最近一次使用发生在什么时候
- 哪一类复盘更值得继续处理

建议包含以下内容：

- 页面标题：`AI 复盘中心`
- 副标题：强调“统一回看简历优化与模拟面试结果，决定下一步行动”
- 返回工作台入口
- 3 到 4 张概览卡

概览卡建议字段：

- 全部复盘记录数
- 简历复盘条数
- 模拟面试条数
- 最近一次记录时间

如果当前后端无法一次性直接返回分类聚合统计，可由前端基于当前已拉取列表做轻量计算，不要求为此新增接口。

### 6.2 主工作区

主工作区固定采用左右分栏：

1. 左侧历史列表与筛选栏
2. 右侧详情工作区

不建议在当前阶段做成手机式上下堆叠主布局。

## 7. 左侧历史列表与筛选

### 7.1 左侧区域职责

左侧区域负责：

- 类型切换
- 列表浏览
- 选中态管理
- 删除入口
- 空态与加载态反馈

### 7.2 推荐筛选结构

当前真实能力下，推荐只保留轻量筛选：

- 一级切换：
  - `全部`
  - `简历复盘`
  - `模拟面试`
- 次级能力：
  - 分页或“加载更多”

说明：

- 列表主筛选直接映射 `taskType`
- 不要求首版支持服务端关键词搜索
- 若模板希望加入前端本地搜索，只能作为非阻塞增强，不得写成依赖后端搜索接口
- 当前正式实现已采用“加载更多 + 已加载数量 / 总量 / 页码提示”的轻分页表达，不再保留“分页占位”文案。

### 7.3 历史列表项字段

每条列表项应统一展示：

- 类型标签
- 创建时间
- 摘要
- 积分消耗
- 当前状态
- 进入详情的选中态

字段映射建议：

- 类型标签
  - `RESUME` 显示为 `简历复盘`
  - `INTERVIEW_TEXT` 显示为 `模拟面试`
- 积分消耗
  - 使用 `pointsConsumed`
  - 允许文案写成“消耗 0 积分”或“消耗 25 积分”
- 状态
  - 简历复盘默认显示为 `已生成`
  - 面试复盘优先展示 `status`，例如 `COMPLETED`

### 7.4 列表项视觉要求

列表项不应只是一行文字。

建议每项至少包含：

- 顶部一行：类型标签 + 时间
- 中间：摘要两行以内截断
- 底部：积分消耗 / 状态 / 进入详情提示

选中态必须明显，可通过以下任一方式表达：

- 左侧高亮边条
- 外层描边加强
- 轻微背景色变化

### 7.5 左侧空态

当没有任何历史记录时，左侧与右侧都不应留空白。

空态必须包含：

- 一句说明：当前还没有可复盘记录
- 两个主 CTA：
  - 去 `/ai/resume`
  - 去 `/ai/interview`

## 8. 右侧详情工作区

### 8.1 总体原则

右侧工作区不是单纯的“详情面板”，而是本页的真正主舞台。

它必须：

- 默认占据主要阅读面积
- 根据当前类型切换不同的详情结构
- 保持主操作清晰

### 8.2 详情区公共区域

无论简历还是面试，都建议在顶部放一个统一的详情头部，包含：

- 当前记录标题
- 创建时间
- 类型标签
- 积分 / 配额说明
- 主操作按钮区

主操作按钮区按当前类型变化，但位置应保持稳定。

## 9. 简历复盘详情设计

### 9.1 简历详情必须包含的模块

1. 复盘摘要
2. 亮点
3. 风险
4. 建议
5. 结构完整度地图
6. 改写沙盘
7. 原始输入上下文
8. 操作区

### 9.2 简历详情字段映射

顶部头部建议展示：

- `summary`
- `scoreLabel`
- `targetRole`
- `targetContext`
- `inputMode`
- `pointsConsumed`
- `createdAt`

### 9.3 各模块要求

- 复盘摘要
  - 以一段高可读摘要卡呈现 `summary`
- 亮点
  - 对应 `strengths`
- 风险
  - 对应 `risks`
- 建议
  - 对应 `suggestions`
- 结构完整度地图
  - 对应 `structureItems`
  - 每项展示 `label`、`score`、`tip`
- 改写沙盘
  - 对应 `rewriteItems`
  - 每项展示 `title`、`problem`、`beforeText`、`afterText`
  - 若 `isHeuristic=true`，应增加“系统 fallback 生成”提示
- 原始输入上下文
  - 展示 `jobDescription`
  - 文本模式下展示 `resumeText`
  - PDF 模式下展示 `pdfFileName`

### 9.4 简历详情主操作

简历详情区必须预留以下操作：

- `继续打磨`
  - 跳转 `/ai/resume`
  - 当前只做回流 CTA，不要求本轮自动带回完整草稿
- `导出复盘`
  - 可对接 `GET /api/v1/ai/resume/export/{recordId}`
  - 若本轮模板暂不接导出，可保留按钮位并标注为后续接线
- `删除记录`
  - 调用 `DELETE /api/v1/ai/history/resume/{recordId}`
- `找导师看看`
  - 跳转 `/mentors`

## 10. 模拟面试复盘详情设计

### 10.1 面试详情必须包含的模块

1. 会话概览
2. 消息时间线
3. 总结评分
4. 优势
5. 短板
6. 建议
7. 操作区

### 10.2 面试详情字段映射

顶部头部建议展示：

- `targetRole`
- `mode`
- `status`
- `prepaidPoints`
- `reservedQuotaWeight`
- `replyRoundUsed` / `replyRoundLimit`
- `createdAt`
- `summaryGeneratedAt`

### 10.3 各模块要求

- 会话概览
  - 展示目标岗位、会话模式、结束原因、是否由 AI 主动结束
- 消息时间线
  - 对应 `messages`
  - 必须明确区分用户、AI、系统
  - 每条消息展示发送角色、文本内容与时间
- 总结评分
  - 对应 `summary.overallScore`
- 优势
  - 对应 `summary.strengths`
- 短板
  - 对应 `summary.weaknesses`
- 建议
  - 对应 `summary.suggestions`

### 10.4 面试详情异常兼容

若当前会话存在以下情况，UI 必须能优雅降级：

- `summary` 为空
- `summaryGeneratedAt` 为空
- `messages` 很长

此时应：

- 继续展示会话信息和消息时间线
- 在总结区给出“本次会话尚未生成总结”或同义提示
- 仍允许用户执行“再次练习”与“删除记录”

### 10.5 面试详情主操作

面试详情区必须预留以下操作：

- `再次练习`
  - 跳转 `/ai/interview`
- `删除记录`
  - 调用 `DELETE /api/v1/ai/interview/sessions/{sessionId}`
- `找导师复盘`
  - 跳转 `/mentors`

## 11. 跨模块 CTA 规则

本页需要明确承担学生后续行动分发职责。

页面内必须出现以下跨模块 CTA：

- 去 `/ai/resume`
  - 用于继续打磨简历
- 去 `/ai/interview`
  - 用于再次练习
- 去 `/mentors`
  - 用于把 AI 复盘结果转化为人工咨询动作

CTA 的位置建议：

- 顶部概览区至少一处
- 详情工作区主操作区至少一处

## 12. 宽屏桌面端视觉与交互约束

### 12.1 当前验收基线

- 本页当前以宽屏桌面端为唯一正式验收基线
- 移动端 / 平板适配不作为本轮模板验收阻塞项

### 12.2 布局建议

- 页面宽度建议与当前学生工作台保持同级别大容器
- 左栏建议固定或接近固定宽度
- 右栏详情区承担主要滚动
- 顶部概览层与主工作区之间需要明确层级分隔

### 12.3 视觉方向

视觉语言应与当前学生端正式页面保持同一产品宇宙：

- 明亮桌面端
- 轻玻璃卡片或高可读白底卡片
- 明显但克制的状态色
- 强调“分析工作台”而不是“聊天页”

不建议：

- 做成单列博客式长文页
- 做成全黑命令行风格
- 做成只有表格和分页器的后台页

## 13. 加载态、空态、错误态与删除反馈

### 13.1 加载态

- 左侧列表和右侧详情应分别支持 skeleton
- 不应使用整页白屏阻塞

### 13.2 空态

- 无记录时提供引导说明与两个 AI 主 CTA
- 某一筛选下无结果时，仅替换左侧列表空态，右侧保留说明卡

### 13.3 错误态

- 列表加载失败与详情加载失败要区分展示
- 允许用户单独刷新列表或详情

### 13.4 删除反馈

- 删除前需要二次确认
- 删除成功后，左侧列表立即移除对应项
- 若删除的是当前选中项，应自动切换到下一条可用记录；若已无记录，则进入空态

## 14. 非目标与边界

当前本页明确不承担：

- 新建 AI 任务
- 重新生成简历报告的服务端复用接口
- 在本页内直接继续一场旧面试会话
- 复杂多维筛选、趋势图与成本分析后台能力
- 独立移动端专项设计

## 15. 验收标准

1. 用户能够在同一页面中区分并切换简历复盘与模拟面试复盘。
2. 左侧历史列表至少能稳定展示类型、时间、摘要、积分消耗、状态与选中态。
3. 右侧简历详情能完整展示摘要、亮点、风险、建议、结构地图与改写沙盘。
4. 右侧面试详情能完整展示会话信息、消息时间线、总结评分、优势、短板与建议。
5. 页面内可稳定回流 `/ai/resume`、`/ai/interview`、`/mentors`。
6. 页面设计不假设新的后端接口，能直接基于当前真实契约落地。
