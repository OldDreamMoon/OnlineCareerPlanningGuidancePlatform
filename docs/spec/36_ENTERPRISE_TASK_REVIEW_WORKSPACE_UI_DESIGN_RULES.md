# 企业任务审核工作区 UI 设计规则

> 文档状态：`evolving`
> 当前版本：2026-04-09
> 适用范围：企业端 `/enterprise/tasks/:taskId`
> 用途：以当前真实代码为准，固定企业单任务审核工作区的桌面端布局、交互入口与轻量闭环边界。

## 1. 文档目标

本文件不是接口文档，也不是逐像素视觉稿。

它的目标是：

- 明确企业审核页当前已经是独立深度工作区，而不是普通详情页
- 固定“提交队列 + 连续阅读区 + 弹窗/抽屉动作”的当前形态
- 避免页面再次回退到旧的右侧常驻动作栏或教学式说明页
- 让后续前端、文档与测试都按真实实现收口

一句话总结：

`企业任务审核工作区是“围绕单个任务集中阅读学生提交、做出结果决策并留下处理记录”的桌面工作台。`

## 2. 页面定位

`/enterprise/tasks/:taskId` 的正确定位不是：

- 普通详情页
- 发布页的回显页
- 完整 ATS 招聘后台
- 实时聊天或面试排班页

它的正确定位是：

- 单任务审核工作区
- 学生提交阅读与筛选决策的主页面
- 任务要求、联系方式、结果通知与处理记录的承接页

## 3. 页面职责边界

### 3.1 本页负责什么

- 查看单任务的学生提交队列
- 搜索与筛选当前任务下的提交
- 阅读提交正文、附件与平台证据
- 查看任务要求
- 查看学生向企业开放的联系方式
- 发出继续接触或未入选通知
- 回看提交级历史处理记录

### 3.2 本页不负责什么

- 企业资料维护
- 多任务搜索与总览
- 完整聊天线程
- 面试排班
- offer 发放
- 录用结果核验

## 4. 当前真实信息架构

当前页面以宽屏桌面端为基线，采用以下结构：

1. 顶部任务摘要栏
2. 左侧提交队列
3. 右侧主阅读区
4. 查看任务要求弹窗
5. 联系方式 / 处理记录右侧抽屉
6. 结果动作配置弹窗
7. 发送前确认弹窗

当前不再保留旧版右侧“状态与动作侧栏”。

### 4.1 顶部任务摘要栏

顶部摘要栏当前展示：

- 返回任务中心
- 任务标题
- 任务状态
- 截止时间
- 提交数量
- 待处理数量

页面标题下方的说明文案当前也已收口为一句简洁的阅读指引，不再堆叠解释性提示块。

### 4.2 左侧提交队列

左侧队列是当前任务下的提交分诊入口。

每个提交项当前展示：

- 学生真实头像
- 学生名称
- 提交时间
- 当前状态
- 前 2 个画像标签摘要
- 近 7 天社区贡献分
- 提交摘要

当前筛选与搜索能力以真实代码为准，包括：

- 关键词搜索
- 状态页签：`全部 / 待处理 / 继续接触 / 未入选`
- 快捷筛选按钮：`仅看待处理 / 查看继续接触 / 清空筛选`
- 最低贡献分筛选

当前页面已去除画像标签筛选栏，不再把标签筛选作为主交互入口。

### 4.3 右侧主阅读区

右侧主区当前采用“头部操作栏 + 连续阅读流 + 底部动作区”的结构。

#### 阅读区头部

当前展示：

- 当前选中学生头像与姓名
- 提交 ID
- 提交状态
- 提交时间
- 3 个辅助动作：
  - `查看任务要求`
  - `联系方式`
  - `处理记录`

#### 连续阅读流

当前正文区域不再切换页签，而是把内容合并为同一阅读流：

1. 概览
2. 正文说明
3. 附件链接
4. 平台证据

平台证据当前展示：

- 近 7 天社区贡献分
- 画像标签
- 画像更新时间

阅读区采用容器内滚动，避免把整页继续撑高。

#### 底部动作区

当前主动作已收口到阅读区底部中部，统一展示为 3 个按钮：

- `继续接触`
- `未入选通知`
- `处理下一位待审核`

这 3 个按钮当前属于页面主动作，不再分散到右侧独立动作栏。

## 5. 当前结果动作流

### 5.1 继续接触

继续接触当前通过独立弹窗配置，而不是页面常驻表单。

当前可配置内容：

- `contactIntent`
  - 继续沟通
  - 进一步交流
  - 邀请面试
  - 录用意向
- `actionNote` 补充说明
- `syncEmailReminder` 是否同步请求邮件提醒

### 5.2 未入选通知

未入选也通过独立弹窗配置，当前可配置内容：

- `rejectTemplate`
- `actionNote` 补充说明
- `syncEmailReminder` 是否同步请求邮件提醒

### 5.3 发送前确认

两类动作在正式提交前都会再进入确认弹窗，确认后才调用审核接口。

### 5.4 学生可见文案与结构化字段

当前审核链路的真实语义为：

- `reviewComment`
  - 学生可见结果说明
- `contactIntent`
  - 继续接触意图
- `rejectTemplate`
  - 未入选模板
- `reviewNote`
  - 补充说明
- `syncEmailReminder`
  - 是否显式请求邮件渠道

## 6. 辅助信息入口

### 6.1 查看任务要求

当前通过 `TaskRequirementsModal` 弹窗查看，承接：

- 任务背景与交付要求
- 奖励说明

弹窗中已去除旧版四张顶部摘要卡，只保留真正需要阅读的任务内容。

### 6.2 联系方式 / 处理记录

当前通过 `ReviewAssistDrawer` 右侧抽屉查看。

联系方式抽屉当前展示：

- 邮箱
- 手机
- 微信
- 外部主页与社交链接

社交链接当前已带上平台图标，不再只显示纯文本。

处理记录抽屉当前展示：

- 提交创建
- 继续接触
- 未入选
- 因任务关闭而自动结束等真实事件

这些记录当前已由后端真实事件表驱动，不再由前端临时拼接。

## 7. 数据与交互原则

### 7.1 旧数据缓存与静默刷新

当前审核工作区已采用“先读旧快照，再后台刷新”的工作区模式：

- 进入页面先尝试读取本地 task-review snapshot
- 有快照时先展示最近一次可用审核内容
- 后台再静默拉取最新任务与提交数据
- `?submissionId=` deep-link 仍可直接定位指定提交

### 7.2 学生身份元素

当前企业审核页中的学生身份元素已统一接入真实学生头像元数据，不再只显示姓名首字母。

### 7.3 已移除的旧能力

以下旧能力当前已从前后端与页面中移除，不应再写回文档：

- 企业内部审核备注
- 右侧常驻状态与动作区
- 页面内“打开通知中心”按钮
- 画像标签筛选栏

## 8. 产品边界

企业审核页当前只承接：

- 审核决策
- 结果通知
- 一次轻量继续接触
- 平台内处理留痕

它不承接：

- 长期消息沟通
- 面试流程推进
- offer 管理
- 入职与录用证明

## 9. 当前实现补充（2026-04-09）

- 当前真实页面已从旧的三栏常驻动作结构，收口为“左侧提交队列 + 右侧主阅读区 + 弹窗/抽屉动作流”的组合。
- 阅读区当前已把 `概览 / 正文说明 / 附件链接 / 平台证据` 合并为连续阅读流，并改为容器内滚动。
- 处理动作当前统一集中在阅读区底部，不再分散在右侧侧栏。
- 任务要求弹窗、联系方式/处理记录抽屉、结果配置弹窗与确认弹窗均已真实落地。
- 处理记录已由真实历史事件表返回，继续接触 / 未入选提交后可立即回看对应留痕。

## 10. 验收标准

1. 企业能在当前页面稳定阅读同一任务下的学生提交，并快速切换不同学生。
2. 企业能通过弹窗或抽屉完成任务要求查看、联系方式查看、处理记录回看与结果动作配置。
3. 企业能发出继续接触或未入选结果，并在页面内立即看到真实留痕。
4. 页面在数据较多时仍保持桌面工作区形态，不回退为整页被内容无限撑长的旧结构。
