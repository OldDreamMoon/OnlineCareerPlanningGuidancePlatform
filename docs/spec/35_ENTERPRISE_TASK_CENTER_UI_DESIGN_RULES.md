# 企业任务中心 UI 设计规则

> 文档状态：`evolving`
> 当前版本：2026-04-09
> 适用范围：企业端 `/enterprise/tasks`
> 用途：为后续 UI / 前端 / 模板 Agent 提供企业任务中心的统一设计基线，并与企业工作台、任务发布页、任务审核工作区保持稳定职责边界。

## 1. 文档目标

本文件不是接口文档，也不是像素级视觉稿。

它的目标是：

- 明确企业任务中心是“多任务管理页”，而不是工作台摘要的延长版
- 锁定任务中心应承担的搜索、筛选、状态识别与进入审核工作区职责
- 让企业端形成和导师端订单中心类似的稳定中枢页

一句话总结：

`企业任务中心应该被设计成“企业查看全部任务、判断先处理哪一个任务”的主页面。`

## 2. 页面定位

`/enterprise/tasks` 的正确定位不是：

- 工作台里的一张大卡片
- 单任务详情页
- 发布页的历史记录区

它的正确定位是：

- 企业的多任务管理中心
- 对任务进行搜索、筛选、状态识别与进入审核工作区的主入口

## 3. 页面职责边界

### 3.1 本页负责什么

- 任务总览卡片
- 关键词搜索
- 状态筛选
- 截止时间识别
- 提交数量回显
- 关闭/重开任务
- 进入任务审核工作区

### 3.2 本页不负责什么

- 编辑完整任务表单
- 深度阅读单个学生提交
- 发继续接触通知的主流程
- 完整认证资料维护

## 4. 页面信息架构

本页建议采用宽屏桌面端五段结构：

1. 页面头部
2. 总览卡片区
3. 搜索与筛选区
4. 任务列表区
5. 快照抽屉 / 侧栏

### 4.1 页面头部

必须包含：

- 页面标题：`任务中心`
- 副标题：强调“管理任务状态、识别优先级、进入审核工作区”
- 发布新任务按钮
- 返回工作台按钮

### 4.2 总览卡片区

建议展示：

- 进行中任务
- 即将截止任务
- 有提交待处理的任务
- 已结束任务

这些卡片的目的是帮助企业先知道“哪里要优先处理”，而不是展示复杂经营指标。

### 4.3 搜索与筛选区

建议正式保留以下能力：

- 关键词搜索
  - 搜标题 / 关键词
- 状态筛选
  - 全部
  - 进行中
  - 已结束
  - 即将截止
- 提交筛选
  - 有提交
  - 待处理
  - 已有继续接触结果

### 4.4 任务列表区

每一项至少展示：

- 任务标题
- 截止时间
- 当前状态
- 提交数量
- 最近更新时间
- 快捷动作
  - 查看快照
  - 进入审核工作区
  - 关闭 / 重开

### 4.5 快照抽屉 / 侧栏

任务中心可以提供一个轻量详情快照，而不是完整详情页。

建议展示：

- 任务背景摘要
- 奖励说明
- 当前提交数量
- 已继续接触数量
- 最近一次处理时间

## 5. 状态语义建议

推荐页面层状态：

- `进行中`
- `即将截止`
- `已结束`
- `已完成筛选`

不要直接把页面语义做成：

- “招募中”
- “录用中”
- “HR 跟进中”

因为企业端在当前毕设中不是完整招聘系统。

## 6. 视觉与交互建议

本页可参考：

- 导师端 `/mentor/orders` 的多单管理逻辑

但企业任务中心应更轻：

- 重点是任务，不是学生消息线程
- 重点是状态和入口，不是复杂弹窗表单

建议整体气质：

- 商务感
- 中等信息密度
- 颜色清晰区分状态，但不过度强调风险红色

## 7. 本页明确不纳入范围

- 完整学生详情长页
- 多任务并行协作分配
- 自动评分排序
- 复杂数据驾驶舱

## 8. 验收标准

1. 企业能从任务中心快速识别哪些任务值得先处理。
2. 企业能通过筛选和列表进入单任务审核工作区。
3. 页面能诚实表达任务状态，不越界承担完整招聘流程。
4. 任务中心与工作台、发布页、审核工作区职责分明。

## 9. 当前实现补充（2026-03-26）

- 当前真实页面 [`/enterprise/tasks`](apps/web/src/pages/EnterpriseTaskCenterPage.tsx) 已按本规则形成“头部 + 总览卡 + 搜索筛选 + 列表 + 右侧快照”的多任务管理页。
- 当前任务中心已正式改接后端聚合接口 `GET /api/v1/bounty/enterprise/task-center`，由后端统一返回企业任务列表、状态计数与最近 6 条提交快照，不再由前端逐任务拉取 submission 后本地拼装。
- 页面当前已采用“旧快照先渲染 + 后台静默刷新”的工作区模式；首次进入时优先展示本地最近一次可用的任务中心快照，再静默拉取最新数据。
- 任务中心当前同时承接三类聚焦回流：
  - `createdTaskId`：发布成功后自动聚焦新任务
  - `editedTaskId`：编辑成功后自动聚焦并提示“修改已同步”
  - `taskId`：兼容企业工作台旧入口与旧快照跳转
- 顶部筛选区当前真实支持：
  - 关键词搜索
  - 状态筛选：`全部 / 进行中 / 即将截止 / 已完成筛选 / 已结束`
  - 提交筛选：`全部 / 有提交 / 待处理 / 已有继续接触结果`
- 右侧快照中的“最近提交与处理状态”当前已为每条 submission 提供“继续处理该提交”入口；主按钮也会优先跳到当前任务最值得先看的那条提交。
- 右侧快照中的学生身份元素当前已统一接入真实学生头像元数据，不再只显示首字母占位。
- 右侧快照底部 CTA 当前已从泛化的“继续发布任务”收口为“编辑任务信息”；若任务已有中选结果，则会锁定编辑入口，避免与真实业务状态冲突。
- 任务管理按钮当前已从仅图标语义收口为明确文案：
  - `OPEN` 任务展示“关闭任务”
  - `CLOSED` 且无中选结果的任务展示“重新开放”
