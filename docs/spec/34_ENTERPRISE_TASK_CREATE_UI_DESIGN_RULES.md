# 企业任务发布页 UI 设计规则

> 文档状态：`evolving`
> 当前版本：2026-03-26
> 适用范围：企业端 `/enterprise/tasks/create`
> 用途：为后续 UI / 前端 / 模板 Agent 提供企业任务发布页的统一设计基线，避免企业发布流程被做成过于简陋的单表单或扩张成完整 JD 管理系统。

## 1. 文档目标

本文件的目标不是接口细节，而是确定页面职责和信息结构。

它要解决的是：

- 企业如何清晰地发布一个可被学生理解的真实任务
- 任务说明、交付要求和奖励信息如何在一页内讲清
- 页面如何兼顾编辑效率和发布前确认

一句话总结：

`任务发布页应该被设计成“企业把任务背景、交付要求和奖励规则说清楚后再正式发布”的工作台。`

## 2. 页面定位

`/enterprise/tasks/create` 的正确定位不是：

- 复杂招聘 JD 编辑器
- 管理后台的表单页
- 单任务审核页

它的正确定位是：

- 企业端发布任务的主入口
- 企业整理需求和交付标准的页面
- 企业发布前最后确认任务可读性的页面

## 3. 页面职责边界

### 3.1 本页负责什么

- 填写任务标题
- 说明任务背景
- 明确交付要求
- 说明奖励与继续接触预期
- 设置截止时间
- 选择任务方向标签 / 适合人群
- 发布前预览

### 3.2 本页不负责什么

- 审核学生提交
- 关闭/重开任务的主操作页
- 与学生聊天
- 真实业务成果验证
- 自动评分

## 4. 页面正式功能范围

本页建议固定包含以下 6 个区块：

1. 页面头部
2. 任务核心信息区
3. 交付要求区
4. 任务属性区
5. 发布前提示区
6. 任务预览 / 提交区

## 5. 页面信息架构

建议采用宽屏桌面端双栏结构：

- 左侧：编辑主区
- 右侧：任务预览与发布说明

### 5.1 页面头部

建议包含：

- 页面标题：`发布企业任务`
- 副标题：强调“把背景、要求和奖励说明清楚”
- 返回工作台按钮
- 返回任务中心按钮

### 5.2 任务核心信息区

必须包含：

- 任务标题
- 任务背景
- 你希望学生解决什么问题

标题应避免过于抽象，建议支持一句辅助说明：

- 例如：`让学生先知道任务做什么，而不是只看到岗位名词`

### 5.3 交付要求区

这是本页最重要的区块之一。

建议至少支持：

- 需要提交什么
- 交付形式
  - 说明文档
  - 设计稿链接
  - 仓库链接
  - 演示链接
- 你最看重什么

本页不要求复杂结构化表单，但应让企业能说清“什么算一次有效提交”。

### 5.4 任务属性区

建议包含：

- 奖励说明
- 截止时间
- 适合方向标签
- 适合人群标签
- 参考资料链接
- 注意事项

### 5.5 发布前提示区

建议通过轻量提示告诉企业：

- 平台内只承接轻量任务闭环
- 真实业务验收与线下面试在平台外继续
- 若后续继续推进学生，可通过平台内“继续接触”入口发送结果通知

### 5.6 右侧任务预览区

右侧建议展示：

- 任务标题预览
- 简要任务卡
- 奖励与截止时间
- 交付要求摘要
- 适合人群标签
- 发布按钮

## 6. 字段设计建议

### 6.1 必填信息

- 标题
- 任务背景
- 交付要求
- 奖励说明
- 截止时间

### 6.2 推荐但不强制的信息

- 任务方向标签
- 适合人群
- 参考链接
- 常见误区提醒

## 7. 交互原则

### 7.1 发布动作

发布动作前建议做轻量检查：

- 是否缺少标题
- 是否缺少任务背景
- 是否缺少交付要求
- 是否缺少奖励说明
- 是否缺少截止时间

### 7.2 编辑与预览关系

建议保持：

- 左侧编辑
- 右侧即时预览

避免：

- 发布后才第一次看到最终卡片效果

### 7.3 草稿能力

草稿能力可作为后续增强，不作为首版阻塞项。

## 8. 文案与视觉建议

本页可以参考：

- 学生端 `/consult/create` 的工作台式双栏结构
- 导师端页面的亮色工作区语言

但企业任务页应该更克制：

- 文案强调“任务、交付、奖励、继续接触”
- 避免强游戏化措辞
- 尽量少用“悬赏”作为唯一用户可见词，更多使用“企业任务”“实战任务”

## 9. 本页明确不纳入范围

- 自动生成招聘 JD
- AI 自动评分规则配置
- 代码沙箱执行
- 多任务批量发布
- 多角色协作审批

## 10. 验收标准

1. 企业能在一页内清楚填写任务背景、要求、奖励与截止时间。
2. 发布前能看到清晰的任务预览。
3. 页面文案诚实表达平台边界，不包装成完整招聘系统。
4. 页面结构支持后续做编辑模式复用。

## 11. 当前实现补充（2026-03-26）

- 当前真实页面 [`/enterprise/tasks/create`](apps/web/src/pages/EnterpriseTaskCreatePage.tsx) 已按本规则形成双栏发布台，并正式复用为编辑模式入口。
- 编辑模式统一通过 `editTaskId` query 进入，不单独增加新路由；进入后会拉取既有任务详情并回填表单。
- 保存时继续复用原发布台视觉壳层与右侧预览区；提交成功后会跳回 `/enterprise/tasks?taskId=...&editedTaskId=...`，由任务中心负责聚焦与提示“修改已同步”。
- richer 字段当前仍诚实复用现有 `bounty.description` 存储，不提前扩专用后端字段；后续若要拆分专门的任务背景 / 交付要求 / 参考资料字段，再独立升级契约。
