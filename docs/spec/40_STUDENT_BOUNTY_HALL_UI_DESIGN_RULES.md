# 学生端企业实战任务大厅 UI 设计需求

> 文档状态：`evolving`
> 当前版本：2026-04-02
> 页面范围：学生端 `/bounty`
> 文档用途：本文件是给“只负责生成前端样式模板、不了解项目上下文”的 AI 使用的自包含设计任务书。请基于本文件独立设计一个全新的宽屏桌面端页面模板，不依赖项目内其他文件。

## 1. 你正在设计什么页面

这是一个给学生使用的“企业实战任务大厅”页面。

页面的核心目标不是招聘投递，也不是岗位列表，而是：

- 让学生浏览企业发布的真实小型实战任务
- 让学生快速判断哪些任务值得点进去看
- 让学生从大厅进入任务详情页，再决定是否提交成果

一句话理解：

`这是一个“真实任务发现页”，不是“简历投递页”。`

## 2. 页面必须传达的业务语义

设计时必须让用户一眼理解以下事实：

- 这里展示的是企业发布的真实任务，不是正式招聘 JD
- 学生可以查看任务要求，并提交自己的成果说明与外部链接
- 平台内只承接“浏览任务 -> 提交成果 -> 回看结果”这条轻量闭环
- 平台不承接完整招聘流程，不做站内聊天、面试安排、录用确认

## 3. 这个页面真实支持什么

页面可以假定自己拿到以下信息：

- 任务 ID
- 企业名称
- 任务标题
- 任务摘要
- 奖励说明
- 任务状态
  - 全部任务中的真实状态会在 UI 中表现为：
    - `进行中`
    - `即将截止`
    - `已结束`
    - `已完成筛选`
- 当前提交数
- 是否“我已经提交过”
- 截止时间
- 最近更新时间

页面当前真实支持以下交互：

- 关键词搜索
- 状态筛选
  - 全部任务
  - 开放中
  - 已关闭
- 分页浏览
- 点击进入任务详情页

## 4. 这个页面明确不支持什么

请不要把页面设计成以下产品：

- 招聘岗位广场
- 简历投递中心
- 企业人才库
- 任务排行榜
- 社交内容流

也不要假装页面已经支持以下能力：

- 排序器
- 复杂高级筛选器
- 标签筛选
- AI 智能推荐分
- 地域筛选
- 企业完整主页展开

如果想增强视觉层次，只能通过版式、状态、信息分组和示例内容表达，而不是凭空增加不存在的功能。

## 5. 宽屏桌面端设计目标

目标用户是正在准备求职的学生。

希望页面给人的第一印象是：

- 真实
- 清晰
- 有行动感
- 偏学生工作台语言，但比普通工作台更有“任务市场”的张力

不希望它看起来像：

- 传统招聘网站
- 冷冰冰的后台表格
- 只有白卡片堆叠的占位页
- 过度游戏化或夸张营销风

## 6. 视觉风格关键词

建议风格关键词：

- 明亮桌面端
- 有主视觉焦点
- 信息层级强
- 卡片式任务市场
- 有明确 CTA

建议视觉方向：

- 以浅底为主
- 可以有柔和但明显的背景氛围层
- 卡片需要有分层，不要所有容器一样重
- 状态色必须清晰，但不要把页面做成风险告警后台

## 7. 页面结构要求

页面按宽屏桌面端设计，建议采用以下五段结构：

1. 顶部导航占位区
2. Hero 总览区
3. 搜索与筛选区
4. 任务卡片网格区
5. 分页 / 空态 / 错误态区

### 7.1 顶部导航占位区

这里不需要重新发明整个站点导航，但页面上方应预留一个学生端统一导航区域。

导航区只需满足模板表达即可，不必展开复杂功能。

建议保留：

- 页面所属身份感
- 当前激活在“企业实战任务”
- 一个次级入口按钮占位，例如“我的咨询单”

### 7.2 Hero 总览区

Hero 是本页最重要的视觉焦点，不能只是一排普通统计卡。

Hero 必须回答：

- 这里是什么页面
- 这里能做什么
- 当前筛选上下文是什么

Hero 建议包含：

- 页面标题：`企业实战任务`
- 一句副标题
  - 要强调“浏览真实任务、提交成果、回看结果”
- 一组任务市场相关的摘要信息
  - 当前总量
  - 当前筛选状态
  - 当前页信息
- 一个明确的主视觉焦点
  - 可以是大标题 + 重点说明 + 状态摘要
  - 不要只放三张平铺数字卡

Hero 禁止做成：

- 单纯宣传 Banner
- 普通后台数据头部
- 和下方筛选栏没有区分度的一整块白色容器

### 7.3 搜索与筛选区

筛选区是功能核心区，必须非常清晰。

需要包含：

- 关键词搜索输入框
- 状态切换器
  - 全部任务
  - 开放中
  - 已关闭
- 应用筛选按钮
- 刷新按钮

设计要求：

- 状态切换器应有很明显的选中态
- 搜索框应看起来像真正会被高频使用
- 操作按钮要有主次关系

### 7.4 任务卡片网格区

任务卡片是列表页的核心内容。

建议采用 3 列或 2-3 列自适应宽屏栅格，但本轮以宽屏桌面端观感为第一优先级。

每个任务卡必须展示：

- 企业名称
- 任务标题
- 一段任务摘要
- 奖励说明
- 当前状态
- 截止时间
- 提交数量
- 最近更新时间
- 是否“我已提交”
- CTA
  - 未提交时：`查看任务`
  - 已提交时：`查看进度`

卡片的信息优先级建议：

第一层：

- 标题
- 状态
- 奖励

第二层：

- 摘要
- 截止时间

第三层：

- 提交数量
- 更新时间
- 我是否已提交

卡片应有明确的悬停反馈，让人感觉“这是可点击、可继续深入的任务入口”。

### 7.5 分页 / 空态 / 错误态区

页面还必须考虑这三种状态：

- 空态
- 错误态
- 分页态

空态不应只写“暂无数据”。

建议空态表达：

- 当前筛选条件下没有任务
- 可以尝试清空关键词、切回全部任务，或者稍后刷新

错误态不应只是一行红字。

建议错误态表达：

- 列表加载失败
- 简短错误说明
- 可重新刷新

分页区需要看起来轻量，但不能太弱。

## 8. 任务卡片需要覆盖的四种典型状态

外部样式 AI 在出模板时，至少要覆盖下面四种卡片状态：

### 8.1 普通开放任务

- 状态：`进行中`
- 特点：还可以提交

### 8.2 即将截止任务

- 状态：`即将截止`
- 特点：时间紧迫，视觉上应比普通任务更有提醒感，但不要做成危险告警

### 8.3 已关闭任务

- 状态：`已结束`
- 特点：不能再提交，但仍可查看详情

### 8.4 我已提交的任务

- 状态可以仍然开放，也可能已关闭
- 特点：必须有明确“我已提交”标识，方便学生快速回看结果

## 10. 文案口径要求

模板里的文案请统一采用以下语气：

- 真实
- 克制
- 清晰
- 不夸张

更适合使用的词：

- 企业实战任务
- 查看任务
- 提交成果
- 回看结果
- 已完成筛选
- 继续接触

尽量少用的词：

- 悬赏令
- 秒杀机会
- 高薪抢人
- 立即投递
- 录用流程

## 11. 设计时必须遵守的限制

请在视觉表现上强化页面，但不要增加下面这些不存在的能力：

- 不要加入“上传本地文件”主入口
- 不要加入“在线聊天”入口
- 不要加入“预约面试”入口
- 不要加入“录用进度条”
- 不要加入“任务智能匹配分”
- 不要加入“筛选排序面板抽屉”

如果需要做更高级的视觉层次，请通过以下方式解决：

- Hero 的主副区分层
- 卡片主次信息层级
- 状态色与徽标系统
- Hover 动效
- 合理的背景氛围

## 12. 交付要求

外部样式 AI 最终应交付一个完整的宽屏桌面端页面模板，至少包含：

- 顶部导航占位
- Hero 区
- 搜索与筛选区
- 至少 6 张任务卡
- 空态
- 错误态
- 分页区

请优先保证：

- 视觉层级清楚
- 信息真实可信
- 看起来像“学生用的真实任务大厅”

而不是只生成一个普通白底列表。
