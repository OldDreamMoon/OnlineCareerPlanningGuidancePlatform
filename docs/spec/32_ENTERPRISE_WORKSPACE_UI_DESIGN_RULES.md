# 企业工作台 UI 设计规则

> 文档状态：`evolving`
> 当前版本：2026-04-09
> 适用范围：企业端 `/enterprise/dashboard`
> 用途：以当前真实代码为准，固定企业工作台的页面定位、信息架构与交互边界，避免首页再次回退成占位页、完整 ATS 或过重的多任务后台。

## 1. 文档目标

本文件不是接口文档，也不是像素级视觉稿。

它的目标是：

- 明确企业工作台当前已经真实承担“企业登录后第一屏”的职责
- 固定首页只做摘要、分诊、回流与轻量运营，不直接承接完整审核流程
- 为企业资料页、任务中心、任务发布页、审核工作区建立稳定分工
- 让后续前端 / 模板 / 文档收口都以现有真实页面结构为基线

一句话总结：

`企业工作台是“轻量任务运营台”，优先回答现在该处理哪项任务、最近发生了什么、下一步去哪里。`

## 2. 页面定位

`/enterprise/dashboard` 的正确定位不是：

- 管理员大盘
- 完整招聘 ATS 首页
- 纯展示型品牌页
- 审核工作区的放大版

它的正确定位是：

- 企业登录后的真实首页
- 企业任务与提交进展的分诊台
- 认证状态、任务节奏与业务提醒的摘要入口

## 3. 页面职责边界

### 3.1 本页负责什么

- 展示企业当前认证状态与首要入口
- 展示任务统计摘要
- 展示需要优先处理的任务
- 展示最新业务提醒
- 展示最新处理记录与继续接触留痕
- 提供发布任务、进入任务中心、回到资料页等快捷动作
- 提供任务详情轻量抽屉

### 3.2 本页不负责什么

- 企业资料完整编辑
- 认证材料完整管理
- 多任务复杂搜索与关闭/重开主流程
- 单任务学生提交的深度阅读与审核决策
- 完整聊天、排班、面试或录用流程

### 3.3 与其他企业页面的分工

- `/enterprise/dashboard`
  - 做摘要、提醒、分诊、回流
- `/enterprise/profile`
  - 做企业资料、Logo、认证状态与通知提醒设置
- `/enterprise/tasks`
  - 做多任务搜索、筛选、状态识别与任务快照
- `/enterprise/tasks/create`
  - 做任务发布与编辑
- `/enterprise/tasks/:taskId`
  - 做单任务审核、联系方式查看、结果通知与历史留痕

## 4. 当前真实信息架构

当前页面以宽屏桌面端为验收基线，采用以下结构：

1. 顶部共享企业工作台顶栏
2. Hero 区
3. 统计卡区
4. 快捷操作区
5. 主工作区
6. 任务详情抽屉

### 4.1 Hero 区

当前 Hero 已收口为轻量身份头图，只保留：

- 更显眼的企业名称展示
- 认证状态 Badge
- 问候语
- 一句简洁说明
- 2 个主操作按钮

当前不再保留：

- Hero 中部“今日重点 / 工作进展”提示卡
- Hero 右侧额外的“通知中心”按钮
- 任何会把首页再次做重的说明型模块

### 4.2 统计卡区

当前首页使用 5 张统计卡表达当前工作量，重点围绕：

- 进行中任务
- 待处理提交
- 即将截止任务
- 已完成结果
- 最近 7 天新增提交

这些卡片只负责表达“现在的任务量与优先级”，不承接经营大盘、曝光量或复杂 BI 指标。

### 4.3 快捷操作区

当前快捷操作明确收口为 4 个业务入口：

- 发布新任务
- 打开任务中心
- 待审核提交
- 企业资料与认证

要求：

- 入口必须直接落到真实页面
- 文案保持业务化，不写技术说明
- 入口数量保持克制，不再继续向首页叠加低频能力

### 4.4 主工作区

主工作区当前采用左右双列：

- 左侧主列：`需要处理的任务`
- 右侧辅列：`最新业务提醒` + `最新处理记录`

#### 左侧：需要处理的任务

每个任务卡当前至少展示：

- 任务标题
- 待处理提交数量
- 截止状态
- 近 7 天新增提交数量
- 最近提交动态
- 两个动作按钮：
  - `去任务中心查看`
  - `查看任务详情`

最近提交动态当前已接入真实学生头像，并直接支持跳到指定 `submissionId` 的审核工作区。

当前首页为了控制高度，任务列表按轻量分页展示：

- 每页 5 条任务

#### 右上：最新业务提醒

当前已收口为提醒轮播卡，而不是长列表。

展示内容包括：

- 企业任务相关提醒
- 企业认证相关提醒
- 直接回到对应业务页的 CTA

当前实现规则：

- 默认展示最近 3 条
- 自动轮播间隔 15 秒
- 用户手动切换后会重置轮播计时
- 通知中心入口保留在卡片标题区与空态 CTA 中

#### 右下：最新处理记录

当前已收口为结果留痕轮播卡，用于回看：

- 已发送继续接触
- 已发送未入选通知
- 审核备注摘要
- 快速回到对应任务审核工作区

当前实现规则：

- 默认展示最近 5 条
- 自动轮播间隔 15 秒
- 用户手动切换后会重置轮播计时
- 若备注较长，可通过独立查看入口阅读完整内容

### 4.5 任务详情抽屉

工作台不直接展开完整审核内容，只提供轻量任务详情抽屉，承接：

- 任务背景
- 希望解决的问题
- 交付要求
- 奖励说明
- 提交与待处理数量
- 最近提交与处理状态快照
- 进入审核工作区 / 编辑任务 / 关闭任务等下一步动作

抽屉仍属于摘要层，不替代任务中心和审核工作区。

## 5. 数据与交互原则

### 5.1 旧数据缓存与后台静默更新

当前工作台已采用“先展示旧快照，再后台静默刷新”的模式：

- 进入页面时优先读取本地 workspace snapshot
- 若已有快照，先展示最近可用内容
- 后台静默刷新成功后再更新页面
- 用户也可手动触发刷新

该策略的目标是保证企业高频切页时的首屏稳定性，而不是等待所有接口完成后再整页阻塞。

### 5.2 首页只做分诊，不做深度操作

首页上的按钮与抽屉必须把用户带到真实业务页，不在首页直接承接：

- 完整任务审核
- 联系方式查看
- 决策表单填写
- 大段认证资料编辑

### 5.3 首页文案必须诚实

企业端在当前毕设范围内只承接：

- 任务发布
- 学生提交查看
- 审核结果通知
- 一次轻量继续接触

因此首页文案不应夸张为：

- 智能人才库
- 全流程招聘中枢
- 自动筛人后台

## 6. 当前实现补充（2026-04-09）

- 当前真实页面已固定为 `Hero + 统计卡 + 快捷操作 + 左侧任务主列 + 右侧提醒/留痕双卡 + 任务详情抽屉` 的结构。
- Hero 已进一步减重，不再保留中部提示卡，也不再在 Hero 内单放通知中心按钮。
- 业务提醒与处理记录都已从旧的页内分页方案收口为轮播卡，分别展示最近 `3` 条与最近 `5` 条。
- `需要处理的任务` 当前仍保留轻量分页，每页 `5` 条，用于控制首页高度并保持左右底边对齐。
- 工作台中的学生身份元素已统一接入真实学生头像元数据，不再只用首字母占位。
- 首页继续只承担“摘要、提醒、分诊与跳转”，不再承接旧的 `dashboard?taskId=...` 兼容语义。

## 7. 验收标准

1. 企业登录后能在首页清楚知道当前认证状态、任务量和下一步入口。
2. 企业能从首页快速进入任务中心、资料页、发布页和指定提交的审核工作区。
3. 首页信息密度在数据增多后仍可控，不因长列表把页面无限拉长。
4. 页面保持“轻量任务运营台”定位，不回退成占位页，也不扩张成完整招聘后台。
