# 学生画像与内容推荐落地蓝图

> **文档状态**：`evolving` · 最后审核：2026-04-15 · 用于沉淀学生画像、导师推荐与画像异步任务的收口方案。

## 1. 文档目标
本文件用于把当前关于学生画像、推荐算法和异步任务的讨论结果收口成可长期复用的 spec 蓝图，避免后续实现再次在“纯规则 / 纯 LLM / 协同过滤 / 内容推荐”之间反复摇摆。

本文件覆盖：
- 学生画像的真实职责边界
- 学生画像 V2 的目标结构
- 导师推荐与后续任务推荐的主算法口径
- 语义增强与 LLM 的可插拔位置
- 画像提取 / 画像总结的异步任务规划

本文件不覆盖：
- 具体页面像素级设计
- 本轮未进入实现的协同过滤实验
- 独立的数仓 / 离线训练平台设计

## 2. 当前收口决策
当前版本正式采用以下口径：

- 学生画像的真相层以本地后端规则与结构化证据聚合为主，不把 LLM 作为画像事实判定来源。
- 学生画像的自然语言表达层先采用模板化总结；后续若需要更自然的文案，可在不改变真相层的前提下接入低频 LLM 润色。
- 推荐系统当前正式主线为“基于内容的推荐 + 规则重排”，不是协同过滤，也不是黑盒大模型直接产榜。
- 语义向量当前只承担“召回增强 / 标签增强 / 解释补强”的职责，不单独决定最终推荐榜单。
- 当前版本正式放弃把协同过滤作为主实现方向；后续若行为数据规模与评估基线充足，可作为增强层重新评估。

截至 2026-04-15，当前主线已落地到以下状态：

- 已实现：学生画像 V2 当前接口结构，包括 `tags / strengthTags / riskTags / evidence / signalLevel / freshnessLevel / headline / summary / nextActions / summaryVersion / updatedAt`。
- 已实现：学生画像表达层的模板总结，以及管理员后台对 `student.portrait.async-refresh.enabled`、`student.portrait.summary.mode` 与 `student.portrait.summary` 场景的配置承接。
- 已实现：低频 LLM 润色链路，但当前仅在高价值触发中低频启用；社区轻互动、公开资料读取与凌晨批刷新不会默认触发 LLM。
- 已实现：导师推荐正式采用“学生画像 + 最近简历 / 面试信号 + 本地 embedding 召回 + 规则重排 + 可解释理由 + 运行留痕”。
- 未实现：学生 -> 企业任务推荐正式接口。
- 未实现：画像异步任务 `PORTRAIT_REFRESH / PORTRAIT_SUMMARY` 的正式 worker 接入；当前仍以同步刷新为主，仅保留蓝图与底座规划。

## 3. 为什么当前不做协同过滤
当前项目不把协同过滤纳入主线实现，原因如下：

- 平台仍处于冷启动阶段，真实浏览、收藏、咨询下单、任务申请等行为矩阵不足。
- 即便能通过演示数据勉强跑通，也很难给出有说服力的离线评估或线上提升证据。
- 学生画像与导师 / 任务对象本身已经具备较强的文本、标签与场景信息，更适合优先采用内容匹配。
- 毕设答辩更需要“可解释、可复现、可展示”的工程方案，而不是形式上堆砌算法名词。

因此，当前阶段的推荐主线应统一为：

- 学生画像建模
- 内容语义召回
- 规则重排
- 运行留痕与解释输出

## 4. 学生画像的正式定位
学生画像不是“随手生成一段 AI 文案”，而是平台内部的结构化中间真相层。

它需要同时服务于：

- 学生资料中心与学生工作台的成长反馈
- 导师推荐与后续任务推荐的匹配输入
- 企业任务审核、导师履约等跨模块快速理解
- 论文 / 答辩中的“学生成长与个性化服务”叙述

因此，学生画像必须拆成两层：

### 4.1 真相层
负责输出可复核、可解释、可追踪的结构化信息，包括：

- 方向标签
- 优势标签
- 风险标签
- 证据计数
- 信号强弱
- 新鲜度

### 4.2 表达层
负责把真相层翻译成用户能看懂的结论，包括：

- 标题型概述
- 一段总结文案
- 当前优势
- 当前短板
- 下一步建议

规则：
- 真相层优先级高于表达层。
- 表达层不能推翻真相层。
- 即使后续接入 LLM，也只能消费真相层输出，而不是反向决定标签或结论。

## 5. 学生画像 V2 目标结构
当前真实接口已经返回以下结构；其中 LLM 润色属于可选表达层增强，不改变真相层字段语义：

```json
{
  "portrait": {
    "tags": [
      {"code": "TARGET_DIRECTION_BACKEND", "label": "后端求职导向", "source": "PROFILE", "confidence": 0.90}
    ],
    "strengthTags": [
      {"code": "SKILL_PROGRESS_ACTIVE", "label": "技能成长清晰", "source": "SKILL_PROGRESS", "confidence": 0.82}
    ],
    "riskTags": [
      {"code": "INTERVIEW_COMMUNICATION_GAP", "label": "面试表达结构待补强", "source": "AI_INTERVIEW", "confidence": 0.84}
    ],
    "evidence": {
      "masteredSkills": 3,
      "learningSkills": 2,
      "interviewMessages7d": 6,
      "posts7d": 1,
      "comments7d": 4,
      "likesReceived7d": 8
    },
    "signalLevel": "NORMAL",
    "freshnessLevel": "RECENT",
    "headline": "后端方向已较明确，当前主要短板在项目表达与回答结构",
    "summary": "你当前的求职方向已经比较清晰，近期也持续在进行模拟面试。结合最近一次简历诊断和面试复盘，项目成果表达与回答结构仍是优先补强项。",
    "nextActions": [
      "补 2 到 3 条可量化项目成果",
      "继续做 1 次围绕目标岗位的模拟面试复盘"
    ],
    "summaryVersion": 2,
    "updatedAt": 1772445600000
  }
}
```

字段说明：

- `tags`
  - 画像总标签池，保留与当前实现兼容的统一入口。
- `strengthTags`
  - 当前优势，供学生端与推荐系统读取。
- `riskTags`
  - 当前短板，供学生端行动建议与导师推荐匹配读取。
- `signalLevel`
  - `WEAK | NORMAL | STRONG`，用于表达当前画像依据是否充分。
- `freshnessLevel`
  - `FRESH | RECENT | STALE`，用于表达画像是否需要重算。
- `headline / summary / nextActions`
  - 属于表达层结果，不能替代结构化标签。
- `summaryVersion`
  - 用于表达层模板或 LLM 方案切换时做缓存和回滚。

## 6. 学生画像信号来源
学生画像的输入信号当前与后续统一使用以下四类：

### 6.1 资料侧
- `targetPosition`
- `skillTags`
- `selfIntro`
- 必要时可纳入 `schoolName / major / grade` 的低权重分类信号，但不作为外发 LLM 的默认输入

### 6.2 行为侧
- 技能进度摘要
- 社区 7 日互动
- 面试 7 日消息量

### 6.3 AI 历史侧
- 最近一次简历诊断 `summary / suggestions / targetRole`
- 最近一次面试总结 `weaknesses / suggestions / targetRole`

### 6.4 运行侧
- 上次刷新时间
- 是否为首次生成
- 是否为弱信号状态

## 7. 画像生成的分层方案
### 7.1 第一层：本地规则真相层
当前和后续都必须保留。

职责：
- 聚合多源信号
- 生成方向 / 优势 / 风险标签
- 计算 evidence、signalLevel、freshnessLevel
- 形成推荐可消费的结构化快照

要求：
- 规则可解释
- 输出稳定
- 对答辩可复核

### 7.2 第二层：模板化表达层
这是当前已正式落地的用户可见能力。

职责：
- 把结构化标签翻译成 `headline / summary / nextActions`
- 保持中文表达自然，但不引入外部模型成本

要求：
- 不依赖 LLM
- 支持按信号强弱切换文案模板
- 支持按方向标签、风险标签和活跃度组合生成不同版本

### 7.3 第三层：可插拔语义增强层
该层用于提升标签识别与推荐语义召回，不直接给用户输出最终结论。

职责：
- 增强方向识别
- 对简历问题、面试问题做主题聚类
- 修正标签置信度
- 增强导师 / 任务内容召回

规则：
- 当前默认实现可继续使用本地 `LOCAL_HASHED_BOW_V1`
- 后续若切到本地中文 embedding 或 AI gateway 独立 embedding 路由，必须保持接口不变
- 语义结果只能增强规则，不应直接覆盖硬规则结果

当前实现说明：
- 导师推荐当前已正式使用本地 `LOCAL_HASHED_BOW_V1` 做召回增强。
- 推荐运行会落库 `student_recommendation_snapshots / mentor_recommendation_snapshots / recommendation_embedding_vectors / mentor_recommendation_runs / mentor_recommendation_events`，用于留痕与复核。

### 7.4 第四层：低频 LLM 润色层
该层当前已具备接入能力，但仍属于可选增强，不是默认主路径。

定位：
- 仅用于把 `headline / summary / nextActions` 写得更自然
- 不决定标签、不决定分数、不决定方向归属

输入要求：
- 只允许传结构化摘要
- 默认不传姓名、手机号、邮箱、微信、完整简历正文、完整面试对话
- 只允许在缓存 miss 且画像版本变化时低频触发

## 8. 推荐系统正式口径
当前推荐系统统一使用“内容推荐 + 规则重排”。

### 8.1 导师推荐
输入：
- 学生画像标签
- 目标岗位
- 技能标签
- 当前问题场景
- 最近一次 AI 简历 / 面试信号

候选导师侧输入：
- 擅长方向
- 服务场景
- 导师简介
- 质量信号
- 可接单状态
- 价格区间

过程：
1. 生成学生推荐快照。
2. 生成导师推荐快照。
3. 用语义向量做召回。
4. 按问题场景、能力短板、目标岗位、质量信号、可接单、价格六维规则重排。
5. 输出可解释的推荐理由。

### 8.2 任务推荐（后续可复用）
同一套画像也可为学生 -> 企业任务推荐提供输入：

- 学生方向标签
- 技能标签
- 活跃度
- 风险标签
- 任务方向与交付要求

当前原则仍然是基于内容推荐，不进入协同过滤。

当前实现状态：
- 本节仍为后续规划，当前没有正式开放的学生 -> 企业任务推荐接口或前端推荐工作面。

## 9. 画像异步任务规划
### 9.1 规划目标
学生画像未来不应完全依赖同步刷新。原因如下：

- 资料更新、社区互动、AI 结果落库都会触发画像变化，完全同步执行容易造成重复计算。
- 表达层若引入模板总结或低频 LLM 润色，更适合异步去重与缓存。
- 推荐快照和语义向量也需要在画像更新后联动失效或重刷。

### 9.2 当前底座选择
下一阶段优先复用当前已落地的 `ai_async_task_jobs + ai_async_task_events` 底座，而不是重新引入第二套任务系统。

规划态建议新增任务类型：
- `PORTRAIT_REFRESH`
- `PORTRAIT_SUMMARY`

规划态建议使用的场景码：
- `STUDENT_PORTRAIT_REFRESH`
- `STUDENT_PORTRAIT_SUMMARY`

当前实现状态：
- 当前只完成了异步任务底座和简历优化处理器，画像刷新 / 画像总结尚未真正接入 worker。
- 当前画像刷新仍以同步服务层刷新为主，并通过触发分层降低重算与 LLM 成本。

### 9.3 触发来源
以下事件可触发画像异步任务：

- 学生资料更新
- 技能进度更新
- 社区发帖 / 评论 / 关键互动阈值变化
- AI 简历优化成功
- AI 面试总结成功
- 定时巡检发现画像过旧
- 首次读取画像但缓存 / 快照缺失

### 9.4 任务拆分建议
#### A. `PORTRAIT_REFRESH`
职责：
- 提取多源信号
- 重算 `tags / strengthTags / riskTags / evidence / signalLevel / freshnessLevel`
- 更新 `student_portrait_snapshots`
- 失效相关缓存
- 标记推荐快照与向量缓存需要重刷

说明：
- 该任务原则上不依赖外部 LLM。
- 若首次读取时当前没有快照，可保留一次同步兜底。

#### B. `PORTRAIT_SUMMARY`
职责：
- 基于最新真相层结果生成 `headline / summary / nextActions`
- 默认采用模板化总结
- 后续若启用 LLM，也只消费结构化摘要输入

说明：
- 该任务可单独开关控制。
- 只有在真相层内容版本变化时才需要重算。

### 9.5 输入快照要求
异步任务的 `input_snapshot_json` 仅保存最小必要信息：

- 触发来源
- 触发时间
- 结构化信号摘要
- 内容 hash / 版本号

默认不保存：
- 完整简历全文
- 完整面试逐字稿
- 手机号、邮箱、微信等敏感信息

### 9.6 去重与幂等
建议规则：

- 同一学生同一场景同时只允许一个进行中的画像任务
- 在短窗口内重复触发时，以最新任务覆盖旧任务，或合并为一次重算
- 任务成功写快照后必须失效画像缓存
- 任务成功写快照后应联动推荐快照 / 向量缓存刷新策略

## 10. 成本与隐私原则
### 10.1 成本原则
- 画像真相层一律本地计算
- 模板总结优先，不以 LLM 作为默认路径
- 若启用 LLM，只能低频触发、按版本缓存、避免页面读取时实时调用

### 10.2 隐私原则
- 真实姓名、手机号、邮箱、微信等字段不得进入画像外发摘要
- 学校、专业、年级等信息默认不作为外发 LLM 的必要输入
- 简历和面试原文不直接外发；只允许外发结构化摘要

## 11. 建议实施顺序
### Phase 1
- 扩展画像结构
- 补模板化总结
- 前端补“概述 / 优势 / 短板 / 下一步建议”

### Phase 2
- 抽象统一的语义向量 provider
- 继续兼容 `LOCAL_HASHED_BOW_V1`
- 让画像标签更正式地进入导师推荐

### Phase 3
- 复用异步任务底座承接画像刷新与画像总结
- 做去重、缓存、重刷策略

### Phase 4
- 视成本和隐私评估结果，决定是否引入低频 LLM 润色
