# 软件需求规格说明 SRS

> **文档状态**：`evolving` · 最后审核：2026-04-18 · 已按当前已部署实现回写；FR 主编号保持稳定，局部说明按最终落地功能补齐。
>

## 1. 系统目标与约束
### 1.1 目标
构建一个模块化单体 Web 系统，实现：多角色服务、AI 能力集成、成长体系、社区互动、咨询订单与支付、企业悬赏模块。

### 1.2 约束
- 周期：6-10 周。
- 架构：Java 模块化单体，不拆微服务。
- 外部依赖：LLM/STT/TTS 服务、Gemini Live 测试链路、Geetest、Resend、支付宝沙箱。
- 部署基线：Linux + Docker Compose + Caddy 反向代理。
- 默认数据库基线：PostgreSQL；历史 MySQL 仅保留为旧 checkpoint / dump / 回滚参考。

## 2. 功能需求（FR）
### 2.1 身份与权限
- `FR-001`：支持 `STUDENT`、`MENTOR`、`ENTERPRISE` 注册登录。
- `FR-001` 补充：正式注册链路支持 `Geetest -> /auth/email/send-code -> /auth/email/verify-code -> emailVerificationToken -> /auth/register(/with-certification)`。
- `FR-002`：支持 JWT 鉴权与刷新机制。
- `FR-003`：受保护接口必须做 RBAC。
- `FR-004`：支持管理员角色和管理接口。
- `FR-004` 补充：支持公开忘记密码链路 `send-code -> verify-code -> change`，并与注册页共享 Geetest proof 校验机制。

### 2.2 用户画像
- `FR-005`：学生画像包含专业、年级、目标岗位、技能标签。
- `FR-006`：导师画像包含领域标签、简介、定价、可用状态。
- `FR-007`：企业画像包含公司信息、联系人身份与招聘方向标签。
- `FR-008`：导师/企业开通支持审核流程。

### 2.3 AI 工具
- `FR-009`：提供简历优化接口。
- `FR-010`：简历优化返回摘要、优势、风险、建议。
- `FR-011`：支持创建面试会话，当前正式支持 `text / voice / live` 三种回答模式。
- `FR-012`：支持多轮面试回复，并支持 SSE / 真流式返回。
- `FR-013`：面试回复包含追问与可选评分，结束后可生成总结报告。
- `FR-014`：支持社区 AI 预回答。
- `FR-015`：支持 AI 破冰私信生成。
- `FR-016`：AI 响应携带 `traceId` 与模型元信息。
- `FR-016` 补充：`live` 测试模式需支持 transcript 回灌到 Java 主链路，并继续沿用正式 summary / history / notification 闭环。

### 2.4 成长与积分
- `FR-017`：返回预设技能树。
- `FR-018`：节点状态支持 `LOCKED/LEARNING/MASTERED`。
- `FR-019`：支持每日签到与连签记录。
- `FR-020`：支持每日微任务。
- `FR-021`：积分变化必须追加到账本。
- `FR-022`：支持积分账本查询。

### 2.5 社区
- `FR-023`：支持社区帖子创建/列表/详情，社区前端按统一模块工作台组织，不为发帖/回帖单独拆业务页面。
- `FR-024`：帖子与评论支持轻量 Markdown 输入与安全渲染，至少覆盖标题层级、正文段落、分点、加粗、引用、代码块与链接。
- `FR-025`：支持点赞/取消点赞，前端可按“有帮助”语义展示。
- `FR-026`：AI 评论或 AI 辅助内容需标记 `is_ai=true` 或等价 AI 标识；自动 AI 首评保留为可选增强能力。
- `FR-027`：管理员可审核并记录审计日志。
- `FR-090`：社区帖子支持问题场景分类与 `resolvedStatus`（如 `OPEN|RESOLVED`），用于求职问答闭环。

### 2.6 咨询与支付
- `FR-028`：学生可创建咨询订单。
- `FR-029`：订单状态机必须按规范流转。
- `FR-030`：支持支付宝沙箱支付发起。
- `FR-031`：支持支付回调验签。
- `FR-032`：回调处理必须幂等。
- `FR-033`：支持模拟支付模式。
- `FR-034`：导师可在咨询消息线程回复。
- `FR-035`：满足条件后订单可关闭。

### 2.7 企业任务 / 悬赏
- `FR-036`：企业可发布任务。
- `FR-037`：学生可提交链接/文本成果。
- `FR-038`：企业可审核并标记结果。
- `FR-039`：支持可选 AI 文本点评（不执行代码）。

说明：
- 平台内只承接“任务发布 -> 提交查看 -> 审核结论 -> 结果通知”的轻量闭环。
- 企业对学生成果的真实业务验证、线下面试与最终录用手续可在平台外继续进行。

### 2.8 语音最小闭环
- `FR-040`：支持上传面试音频。
- `FR-041`：支持 STT 转写。
- `FR-042`：支持 LLM 生成追问。
- `FR-043`：支持 TTS 语音合成。
- `FR-044`：STT/TTS 失败自动回退文本模式。
- `FR-044` 补充：系统支持 `live` 实时语音测试模式，但该模式不替代正式 `voice-roundtrip` 链路。

### 2.9 管理能力
- `FR-045`：管理员可管理 AI 提供商与模型路由。
- `FR-046`：可管理 Prompt 模板版本。
- `FR-047`：可切换特性开关（支付模式/语音/AI预答）。
- `FR-048`：可查看 AI 调用日志。

### 2.10 AI 配额与用户分级
- `FR-049`：用户分为 `FREE` / `PREMIUM` 等级，默认 `FREE`。
- `FR-050`：FREE 用户每日有免费 AI 调用额度，超出扣积分。
- `FR-051`：积分不足时返回友好提示（`AI-2201`），不允许调用。
- `FR-052`：PREMIUM 用户不受配额限制。
- `FR-053`：管理员可配置各等级各任务类型的配额策略。

### 2.11 站内通知
- `FR-054`：平台关键事件（AI 简历异步任务、咨询/支付/售后、企业任务结果、认证审核、系统公告）触发统一站内通知；`COMMUNITY` 首版允许有限正式接入，至少覆盖帖子回复、审核结果、举报结果等核心事务事件。
- `FR-055`：前端支持基于 WebSocket 的实时推送，并在浏览器授权场景下结合 Notification API 提供桌面提醒。
- `FR-056`：支持离线消息拉取、重连补偿与未读同步；WebSocket 不是唯一数据来源。
- `FR-057`：支持通知列表、未读数量、单条/全部已读、通知偏好配置与 WebSocket 短票据申请；社区通知需稳定跳转到帖子详情或举报反馈页。

### 2.12 体验增强
- `FR-058`：AI 面试结束后生成总结报告（总体评分、优势、薄弱点、改进建议）。
- `FR-059`：AI 回复支持 SSE 流式输出（面试对话、简历优化场景）。
- `FR-060`：咨询订单关闭后，学生可提交 1-5 星评价与可选文字评价。
- `FR-061`：导师评分由所有评价汇总计算并展示在导师主页。

### 2.13 搜索与筛选
- `FR-062`：导师列表支持按领域标签、价格区间、是否可接单筛选。
- `FR-063`：悬赏任务列表支持按状态、关键词筛选。
- `FR-064`：社区帖子支持按标题关键词、问题场景和标签筛选。

### 2.14 AI 使用历史
- `FR-065`：学生可查看 AI 使用历史（简历优化、面试会话等）。
- `FR-066`：每条历史记录展示时间、类型、消耗积分、概要。

### 2.15 社区标签
- `FR-067`：帖子支持添加标签（如“简历打磨”、“面经分享”、“求职心得”等）。
- `FR-068`：社区列表支持按标签筛选。

### 2.16 导出能力
- `FR-069`：AI 简历优化结果可导出为 PDF（基于标准 PDF 渲染导出）。

### 2.17 密码管理
- `FR-070`：管理员可在后台重置用户密码；登录页同时支持公开“忘记密码”自助重置链路。

### 2.18 内容审查与举报治理
- `FR-071`：统一内容审查引擎返回 `riskLevel`、`action`、`reasonCode`、`traceId`。
- `FR-072`：AI 输入在调用模型前执行审查，命中高风险可阻断（`MOD-1001`）。
- `FR-073`：AI 输出在返回用户前执行审查，支持脱敏替换与阻断（`MOD-1002`）。
- `FR-074`：社区发帖与评论在发布前执行审查，支持 `PASS|REVIEW|BLOCK`。
- `FR-075`：命中 `REVIEW` 的社区内容默认对普通用户不可见，进入待审队列。
- `FR-076`：支持用户举报帖子、评论、用户，含原因分类与补充说明。
- `FR-077`：举报需支持重复举报去重与频控，超限返回 `MOD-1004`。
- `FR-078`：用户可查询本人举报记录与处理状态。
- `FR-079`：管理员可查看举报列表并执行受理/驳回/下架/恢复。
- `FR-080`：管理员可查看待审队列并执行通过/驳回，处置动作写审计日志。
- `FR-081`：管理员可管理敏感词库与审查策略（阈值、动作、白名单）。
- `FR-082`：支持治理开关与回退路径（AI 输入审查、AI 输出审查、社区强审、自动隐藏阈值）。

### 2.19 学生动态画像与社区贡献榜
- `FR-083`：学生资料支持冷启动字段 `skillTags` 与 `selfIntro`。
- `FR-084`：系统基于 `skill_progress`、面试问答、社区互动生成学生动态画像标签。
- `FR-085`：画像结果需返回可解释证据（计数）与最近更新时间。
- `FR-086`：画像支持事件触发刷新（技能进度更新、社区互动）与每日兜底重算。
- `FR-087`：企业在“自身任务提交列表”可按 `portraitTag` 与 `minCommunityScore7d` 筛选。
- `FR-088`：社区提供近 7 天学生贡献榜，评分公式固定为 `post*5 + comment*2 + like*1`。
- `FR-089`：榜单仅统计学生且仅统计 `PASS` 内容，排序为 `score desc -> latestActivity desc -> userId asc`。

### 2.20 企业端轻量闭环增强
- `FR-091`：企业端应提供工作台首页，聚合认证状态、任务统计、待处理提交、最近任务与快捷发布入口。
- `FR-092`：企业端应提供企业资料与认证模块，展示企业基础信息、招聘方向、认证状态与审核备注。
- `FR-093`：企业端应提供任务中心，对任务进行列表管理、状态筛选、截止时间识别、关闭/重开与进入审核工作区。
- `FR-094`：企业端任务审核工作区应拆分“任务说明”和“学生提交审核”两个信息层级，并支持按画像标签、最低贡献分等证据化方式筛选提交。
- `FR-095`：企业在确认某位学生值得继续推进后，应可发起一次轻量继续接触，至少支持站内通知留痕，并可扩展邮件提醒。
- `FR-096`：企业对未继续推进的学生应可发送未入选结果通知，支持鼓励性模板或补充备注。
- `FR-097`：平台对企业与学生的后续接触只承接一次轻量沟通闭环，不承担完整实时聊天、面试排班或录用验证系统。

## 3. 非功能需求（NFR）
- `NFR-001`：受保护接口必须鉴权与鉴权后授权。
- `NFR-002`：支付回调必须验签。
- `NFR-003`：输入校验需防注入与不安全透传。
- `NFR-004`：支付回调幂等。
- `NFR-005`：AI 模块需超时与重试策略。
- `NFR-006`：关键接口可降级。
- `NFR-007`：非 AI 接口 p95 < 500ms。
- `NFR-008`：AI 接口 p95 < 6s（不含外部故障）。
- `NFR-009`：全链路日志带 `traceId`。
- `NFR-010`：错误码按家族规范。
- `NFR-011`：系统可通过 Docker Compose 部署。
- `NFR-012`：订单/支付/积分可审计可追踪。
- `NFR-013`：v1 并发基线为 10 个并发用户，核心接口在此负载下应保持稳定。
- `NFR-014`：内容审查与举报处置动作必须可追踪并带 `traceId`。
- `NFR-015`：审查模块异常时必须可按开关降级，不阻塞核心业务主链路。
- `NFR-016`：社区贡献榜接口在缓存命中场景下 p95 < 500ms。
- `NFR-017`：社区 Markdown 渲染必须执行危险 HTML 过滤与安全白名单控制，不得直接透传脚本或不可信内联事件。

### 4.2 咨询订单状态机
主路径：`CREATED -> PAYING -> PAID -> ANSWERED -> CLOSED`
异常：`FAILED | CANCELED | REFUNDED`

### 4.3 技能节点状态规则
允许：`LOCKED -> LEARNING -> MASTERED`。
禁止反向回退。

### 4.4 悬赏提交状态规则
`SUBMITTED -> REVIEWING -> ACCEPTED | REJECTED`。

## 6. 外部依赖协议
### 6.1 LLM
- 文本主链路采用 OpenAI 兼容协议。
- 关键字段：`model/messages/temperature/max_tokens`。
- 由 AI 模块做供应商差异归一化，并支持 `ROUTED` 模式下的多 provider / 多 route 管理。

### 6.2 STT/TTS
- STT 输入：音频对象或二进制。
- STT 输出：文本 + 置信信息。
- TTS 输入：文本 + 声音配置。
- TTS 输出：音频对象键或流。

### 6.3 验证码与邮件校验
- 注册与公开忘记密码发码当前共用 Geetest proof 校验机制。
- 注册正式提交前需先完成邮箱验证码校验，换取 `emailVerificationToken`。
- 当公开验证码服务未配置时，开发态允许返回调试验证码，但生产口径不依赖该能力。

### 6.4 支付回调
- 先验签再改状态。
- 幂等键使用第三方交易号。

## 7. 数据一致性要求
- `CR-001`：积分余额从账本推导，禁止直接覆写。
- `CR-002`：订单与支付更新需事务保证。
- `CR-003`：重复回调不可产生重复成功事件。
- `CR-004`：关键并发更新使用版本或锁策略。
- `CR-005`：管理动作必须写审计日志。
- `CR-006`：`student_portrait_snapshots` 每个学生仅保留 1 条最新快照（按 `student_user_id` 唯一约束 upsert）。

## 8. 本规格范围
覆盖 v1 的 P0/P1 全部模块（含通知、SSE、评价、搜索、AI 历史、社区标签、PDF 导出、密码重置、内容审查与举报治理等新增功能）与 P2 亮点能力（语音最小闭环 + `live` 实时语音测试模式）。超出范围项按 PRD 处理。

## 9. 决策摘要
- 采用模块化单体。
- 支付双轨并存。
- 语音只做最小闭环并保留文本回退。
- 内容治理采用“规则审查 + 人工复核 + 审计追踪”闭环。

## 11. 验收基线
1. FR 与关键 NFR 均可映射到实现或回退路径。
2. 状态机与错误码通过测试验证。
