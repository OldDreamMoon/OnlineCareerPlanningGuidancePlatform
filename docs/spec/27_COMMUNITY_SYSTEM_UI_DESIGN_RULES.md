## 1. 目标
- 把社区从“简单帖子列表”升级为“求职互助社区”。
- 为学生提供低门槛提问、经验沉淀、问题分流与导师前置决策入口。
- 用统一模块工作台承接发帖、回帖、治理反馈与社区通知回流。
- 在不扩成泛社交平台的前提下，形成可答辩、可演示、可继续迭代的社区前端设计基线。

## 1.1 当前实现补充（2026-03-26）
- `/community/:postId` 右侧“继续深挖问题”CTA 已按角色正式分流：学生回到 `/mentors` 继续寻找一对一支持，导师回到 `/community` 继续答疑，不再共用同一条学生导向 CTA。
- 帖子详情页中的 AI 辅助卡、回复编辑器和举报弹层已经形成同页工作区；举报既可以当前页直接提交，也可以带预填上下文跳转 `/community/reports` 继续完善。
- 企业角色当前仍不进入社区帖子详情主链路，只保留治理反馈与贡献榜只读回流；后续若扩企业社区只读视图，需要单独补文档裁决，不应误判为当前三角色完全对等开放。
- 社区人物入口已开始正式落地：帖子卡、帖子详情、评论区与贡献榜中的学生头像 / 昵称可进入 `/students/:studentUserId`，承接学生公开空间一期页面。

## 2. 定位与边界
### 2.1 模块定位
- 社区是“AI 工具 -> 社区互助 -> 导师咨询”之间的中间层，不是独立于主链路的泛内容平台。
- 社区优先服务求职问题求助、经验分享、轻量互助与治理反馈。
- 社区内容以文本为主，强调清晰表达与可读性，不追求复杂富媒体内容。

### 2.2 结构原则
- 社区按“统一模块 + 少量正式路由 + 高频动作页内完成”组织。
- 不为发帖、回帖、Markdown 预览单独拆业务页面。
- 发帖和回帖均通过当前上下文中的工作台完成，减少跳页和状态切换成本。

### 2.3 当前非目标范围
- 楼中楼评论
- 个性化推荐 / 热门 feed 算法
- 图片、附件、视频等复杂多媒体帖子
- 社区关注关系、私信系统
- 完整所见即所得富文本编辑器
- 社区点赞 / 榜单变化等高频噪音通知

## 3. 用户角色与核心任务
### 3.1 学生
- 发现和自己相似的问题与经验帖。
- 通过发帖和回帖快速获得反馈。
- 在进入导师咨询前先整理问题和背景。
- 通过社区贡献榜和画像联动感知自己的活跃度与成长反馈。

### 3.2 导师
- 参与社区答疑，建立专业可信度。
- 快速进入与自己擅长场景相关的问题讨论。
- 从社区互动中引导学生进一步进入导师咨询。

### 3.3 企业
- 当前不承担完整社区浏览主链路。
- 可后续复用社区贡献榜或画像结果做只读参考，但不在本轮设计中承担社区互动职责。

## 4. 路由与信息架构
### 4.1 正式路由
| 路由 | 页面定位 | 核心职责 |
|---|---|---|
| `/community` | 社区首页 / 互助工作台 | 浏览内容流、筛选、快速发帖、贡献榜预览、社区通知摘要 |
| `/community/:postId` | 帖子详情 / 讨论工作区 | 阅读主帖、查看评论、回复、查看 AI 辅助卡、举报 |
| `/community/reports` | 举报与治理反馈 | 查看我的举报、治理状态、处理结果、预填举报承接 |
| `/community/leaderboard` | 社区贡献榜 | 查看近 7 天贡献榜、公式说明、个人定位、回跳社区/画像 |

### 4.2 页内工作台
- 发帖工作台：挂在 `/community` 内，不单独拆 `/community/create`
- 回帖工作台：挂在 `/community/:postId` 内，不单独拆 `/community/:postId/reply`
- 举报弹层 / 抽屉：在帖子详情或评论项上直接触发，不单独拆举报页；提交后可回到 `/community/reports`
- Markdown 编辑 / 预览：作为编辑器内部状态，不单独拆页面

### 4.3 桌面端优先
- 当前以宽屏桌面端为主要验收基线。
- 社区模块允许存在移动端降级布局，但不把移动端适配作为当前阶段阻塞项。

## 5. 共享设计约束
### 5.1 视觉语言
- 社区沿用 C 端亮色系工作台语言，与学生工作台 / 导师广场保持统一调性。
- 气质应偏“可信、清晰、可读”，避免过度娱乐化和运营化。
- 信息优先级高于装饰性；正文阅读舒适度优先于炫技布局。

### 5.2 模块级单页感
- 即使存在 4 个正式路由，用户体感上也应感到自己始终处于同一个社区空间。
- 统一保留社区头部、筛选语义和辅助动作语义，减少页面割裂。

### 5.3 关键共享组件
- `CommunityModuleLayout`
- `CommunityPostCard`
- `CommunityAuthorIdentity`
- `CommunityMarkdownComposer`
- `CommunityModerationBanner`
- `CommunityNotificationEntry`
- `CommunityEmptyState`

## 6. Markdown 轻编辑器壳层
### 6.1 定位
- 编辑器不是完整富文本系统，而是“增强版文本输入器”。
- 底层统一保存原始 Markdown 文本，展示时统一做安全渲染。

### 6.2 适用范围
- 社区发帖正文
- 帖子详情页中的评论 / 回复输入

### 6.3 必须支持的能力
- 标题层级
- 正文段落
- 无序列表
- 有序列表
- 加粗
- 斜体
- 引用
- 行内代码
- 代码块
- 链接

### 6.4 编辑器形态
- 采用 `textarea + 顶部轻量工具栏 + 编辑/预览切换`
- 工具栏按钮点击后插入或包裹对应 Markdown 语法
- 不要求用户掌握 Markdown 才能完成基础输入
- 预览模式需与帖子详情真实渲染风格保持一致

### 6.5 非目标范围
- 图片拖拽上传
- 表格编辑
- 文件嵌入
- HTML 直通
- 多人协作草稿

### 6.6 安全要求
- 前端渲染时禁止执行危险 HTML、脚本和不可信内联事件
- 若后端后续参与渲染或清洗，仍以“默认不信任原始 Markdown 内容”为原则

## 7. 社区首页 `/community`
### 7.1 页面目标
- 快速发现相似问题与有价值的经验帖
- 在当前页内发起新帖子
- 把社区定位、规则和贡献反馈一次性交代清楚

### 7.2 推荐布局
- 左侧：筛选导航与视图切换
- 中间：帖子内容流
- 右侧：快速发帖、贡献榜预览、规则提醒、社区通知摘要

### 7.3 首页核心模块
- 顶部 Hero
  - 说明社区定位：求职互助、经验沉淀、低门槛提问
  - 展示当前总览状态，如未读社区通知、我的社区分、快速入口
- 筛选区
  - 关键词搜索
  - 问题场景筛选
  - 标签筛选
  - 视图切换：`最新`、`待回答`、`导师参与`、`我的参与`
- 帖子流
  - 使用统一帖子卡片
  - 支持加载态、空态、筛选无结果态
- 右侧发帖工作台
  - 标题输入
  - 问题场景选择
  - 标签选择
  - Markdown 正文输入
  - 规则与发布反馈

### 7.4 帖子卡片必须展示
- 标题
- 作者昵称
- 角色标识（学生 / 导师 / AI）
- 问题场景 / 标签
- 正文摘要
- 评论数
- 有帮助数
- 创建时间
- `resolvedStatus`
- 必要时展示治理状态提示
- 当作者为学生时，头像 / 昵称应可进入学生公开空间；但人物入口不能破坏整张帖子卡片进入详情的主交互。

### 7.5 首页不做的事
- 不承载完整帖子详情阅读
- 不把首页做成重运营推荐 feed
- 不单独建设“发帖结果页”

## 8. 帖子详情 `/community/:postId`
### 8.1 页面目标
- 承接通知回流后的上下文阅读
- 让用户在同一空间内完成阅读、回复、AI 辅助与举报

### 8.2 页面结构
- 主帖头部
  - 标题
  - 作者身份
  - 问题场景 / 标签
  - 已解决状态
  - 发布时间
- 主帖正文
  - Markdown 安全渲染
- AI 辅助区
  - 思路卡 / 回复草稿
  - 与评论流分层展示，不伪装成普通用户内容
- 评论流
  - AI 回复、导师回复、普通回复的身份差异化
  - 必要时展示治理提示
- 回复编辑区
  - 轻量 Markdown 编辑器壳层
  - 发布后的成功 / 待审 / 拦截反馈
- 侧边辅助区
  - 举报入口
  - 帖子状态说明
  - 相关动作提示

### 8.3 AI 内容展示原则
- AI 自动首评如果存在，应保留明显 `AI` 身份样式
- AI 辅助卡不应淹没真实讨论主线
- AI 内容默认是“辅助用户表达”，不是“替代用户讨论”

### 8.4 举报入口
- 举报帖子与举报评论入口统一样式
- 举报动作在当前页直接触发弹层 / 抽屉
- 提交后可跳转或回看 `/community/reports`

### 8.5 人物入口
- 主帖作者身份区中的学生头像 / 昵称可进入学生公开空间
- 评论区中的学生作者身份可进入学生公开空间
- AI 身份内容不进入人物页
- 进入人物页前允许以前端快照方式缓存当前帖子标题、场景和时间线索，供学生公开空间一期展示最近公开足迹

## 9. 举报与治理反馈 `/community/reports`
### 9.1 页面目标
- 让用户理解自己举报了什么、当前状态如何、结果是什么
- 承接从帖子详情和通知中心回流的治理反馈

### 9.2 推荐结构
- 顶部说明区
  - 社区治理规则透明说明
  - 为什么会有待处理 / 已采纳 / 已驳回等状态
- 举报记录区
  - 按时间或状态查看我的举报
- 详情预览区
  - 查看目标类型、目标标题 / 摘要、当前状态、更新时间
- 预填承接区
  - 从帖子页带入的举报信息可继续编辑与回退

### 9.3 状态语义
- `PENDING` -> 待处理
- `ACCEPTED` -> 已采纳
- `REJECTED` -> 已驳回
- `CLOSED` -> 已关闭

## 10. 社区贡献榜 `/community/leaderboard`
### 10.1 页面目标
- 用贡献榜把社区活跃度、成长反馈与画像连接起来
- 强调“可解释的近 7 天反馈”，不是做成纯竞争榜单

### 10.2 推荐结构
- 顶部规则说明区
  - 最近 7 天口径
  - 公式：`post*5 + comment*2 + like*1`
- 榜单主表
  - 排名
  - 昵称
  - 分数
  - 发帖数
  - 评论数
  - 获赞数
- 我的定位区
  - 当前个人位置
  - 与上一档差距的轻量说明
- 跳转区
  - 返回社区
  - 查看画像
  - 查看学生公开空间

### 10.3 设计原则
- 解释清楚比视觉炫技更重要
- 不做复杂趋势图和段位系统
- 不做“榜单变化通知”的强运营玩法
- 榜单中的学生用户名不应只是静态文本，应成为学生公开空间的重要人物入口。

## 11. 社区通知接入规则
### 11.1 首版正式接入范围
- 有人评论了我的帖子
- 我的帖子 / 评论审核结果变化
- 我的举报有处理结果

### 11.2 跳转语义
- 回复通知：优先跳转 `/community/:postId`
- 审核结果通知：优先跳转 `/community/:postId`
- 举报结果通知：优先跳转 `/community/reports`

### 11.3 本轮不接入的社区通知
- 点赞 / 有帮助
- 榜单排名变化
- AI 自动首评生成
- 普通新帖推荐

## 12. 全局状态与反馈
### 12.1 空态
- 社区空态
- 当前筛选无结果空态
- 暂无评论空态
- 暂无举报记录空态

### 12.2 错误态
- 加载失败
- 发布失败
- 回复失败
- 举报失败
- 社区通知跳转目标失效

### 12.3 治理反馈态
- 发布成功
- 进入待审
- 内容被拦截
- 举报已提交
- 举报结果已更新

## 13. 优先级切片
### 13.1 P0
- `/community`
- `/community/:postId`
- 发帖
- 回帖
- 有帮助
- 关键词 / 场景 / 标签筛选
- Markdown 轻编辑器壳层
- Markdown 安全渲染
- 社区回复通知

### 13.2 P1
- `/community/reports`
- `/community/leaderboard`
- 举报结果通知
- 审核结果通知
- `resolvedStatus`
- AI 辅助思路卡 / 回复草稿

### 13.3 P2
- 自动 AI 首评增强
- 编辑器体验进一步美化
- 额外社区通知细分
- 更复杂的首页推荐区

## 14. 非目标范围
- 不做“完整论坛系统”
- 不做“泛社交广场”
- 不做“社区运营平台”
- 不为了社区专门重做整套富文本基础设施

## 15. 验收标准
1. 社区以统一模块工作台形式成立，而不是零碎功能页堆叠。
2. `/community`、`/community/:postId`、`/community/reports`、`/community/leaderboard` 四个正式路由职责清晰。
3. 发帖和回帖均可在当前页面内完成，不依赖额外创建页或回复页。
4. Markdown 轻编辑器壳层可覆盖标题、正文、分点、加粗、引用、代码块与链接。
5. 社区回复通知与关键治理结果通知可稳定跳转到正确页面。
6. 社区设计与学生主链路、画像、导师咨询之间的关系清晰可讲。
