# 导师财务中心 UI 设计规则

> 文档状态：`evolving`
> 最近同步：2026-04-08
> 适用范围：导师端 `/mentor/finance`
> 用途：以当前真实实现为准，定义导师财务中心的页面职责、数据口径与验收边界。

## 1. 页面定位

`/mentor/finance` 当前已经是导师侧正式落地的财务工作页。

它负责：

- 经营结果概览
- 成交 / 退款趋势
- 账单分页列表
- 模拟提现记录与流转
- 从财务视角解释订单状态

它不负责：

- 单笔订单回复
- 资料编辑
- 真实打款
- 复杂税务或钱包体系

一句话：

`财务中心负责看清钱的状态，不负责处理订单正文。`

## 2. 当前真实实现（2026-04-08）

- 页面当前已正式接入，不再通过前端本地全量聚合咨询订单来计算指标
- 财务主数据来自：
  - `GET /api/v1/mentor/finance/overview`
  - `GET /api/v1/mentor/finance/withdrawals`
  - `POST /api/v1/mentor/finance/withdrawals`
  - `POST /api/v1/mentor/finance/withdrawals/{withdrawalId}/status`
- 页面当前采用“旧快照先渲染 + 后台静默刷新”的加载策略
- 提现记录当前由后端持久化留痕，已不再退回浏览器本地临时存储演示
- 账单区当前使用服务端分页，前端每页展示 `8` 条
- 提现记录区当前前台分页每页展示 `3` 条
- 趋势区当前已收口为固定体积图表，不依赖内部滚动区

## 3. 当前真实后端契约

### 3.1 `GET /api/v1/mentor/finance/overview`

当前真实支持：

- `page`
- `size`
- `keyword`
- `status`
- `range`
- `trendRange`

当前真实返回：

- `metrics`
- `trend`
- `bills`

其中：

- `metrics` 提供累计成交额、已完成收入、可提现金额、提现中、已提现、退款金额、评分等聚合值
- `trend` 提供成交 / 退款趋势点
- `bills` 提供账单分页结果

### 3.2 `GET /api/v1/mentor/finance/withdrawals`

当前真实返回导师自己的提现演示记录，用于页面中的提现记录卡和流转回看。

### 3.3 `POST /api/v1/mentor/finance/withdrawals`

当前真实用于创建模拟提现申请。

### 3.4 `POST /api/v1/mentor/finance/withdrawals/{withdrawalId}/status`

当前真实用于推进模拟提现状态，页面当前会在更新后回刷概览与记录。

## 4. 财务口径

### 4.1 当前页面使用的核心口径

- `累计成交额`
- `已完成收入`
- `可提现金额`
- `提现中`
- `已提现`
- `已退款金额`

### 4.2 当前页面不应使用的误导性口径

- `钱包余额`
- `实时到账`
- `银行卡打款中`
- `可立即提现到账`

当前项目仍保持“平台内模拟提现”范围，不能把页面包装成真实结算后台。

### 4.3 账单状态映射

当前建议继续按以下财务视角表达：

| 订单状态 | 财务页表达 | 说明 |
|---|---|---|
| `CREATED` / `PAYING` | 待支付 | 不进入正式成交流水 |
| `PAID` | 已支付待履约 | 已进入成交口径，但服务未完成 |
| `ANSWERED` | 已履约待确认 | 已完成主要服务，等待学生确认 |
| `CLOSED` | 已完成 | 可进入已完成收入与可提现口径 |
| `REFUNDED` | 已退款 | 需要单独统计退款影响 |

## 5. 页面职责边界

### 5.1 财务中心负责什么

- 指标卡
- 趋势图
- 账单筛选与分页
- 账单详情抽屉
- 退款影响提示
- 模拟提现流转

### 5.2 财务中心不负责什么

- 回复学生消息
- 展开完整订单沟通区
- 编辑导师资料
- 审核认证材料

## 6. 当前页面结构

### 6.1 顶部概览区

当前用于展示：

- 页面标题与说明
- 返回工作台 / 去订单中心入口
- 当前账单总量与提现记录量

### 6.2 指标卡区

当前已稳定展示：

- 累计成交额
- 已完成收入
- 可提现金额
- 提现中
- 已退款金额
- 平均评分或闭环相关辅助指标

### 6.3 趋势与风险区

当前趋势区真实使用 `7D / 30D / MTD` 三档切换。

风险区继续承接：

- 退款影响
- 待确认风险

但应保持轻量，不做管理后台式大告警面板。

### 6.4 提现记录区

当前已是正式可用区块，不再是占位模块。

要求保持：

- 记录摘要
- 当前状态
- 创建时间
- 状态推进动作

### 6.5 账单区

当前已由服务端聚合分页返回，页面负责：

- 关键词筛选
- 状态筛选
- 时间范围筛选
- 页码切换
- 导出当前页账单

## 7. 当前实现约束

- 财务中心当前必须以 `GET /mentor/finance/overview` 为权威数据源，不再回退到“拉全量订单后前端本地算”
- 提现记录当前是模拟流转，但状态变化必须落后端记录
- 页面应优先使用本地快照稳定首屏，再静默刷新；不需要前台显式提示“已切到缓存数据”
- 账单详情的作用是解释金额与状态来源，不应膨胀成第二个履约页

## 8. 当前不再成立的旧口径

以下描述已经失效：

- “财务中心仍复用 `/mentor/dashboard + /consult/orders` 前端本地聚合”
- “提现记录只是 `sessionStorage` 演示”
- “账单仍未接服务端分页”

## 9. 验收关注点

- `/mentor/finance` 首屏应可用旧快照快速展示，再在后台完成静默刷新
- 指标卡、趋势图和账单列表的数据源应统一来自 `/mentor/finance/overview`
- 提现记录创建与状态推进后，应能回刷概览金额和记录列表
- 账单区每页应按当前前端规则展示 `8` 条，提现记录区每页展示 `3` 条
- 页面不应出现“真实打款”“银行卡管理”等超出当前实现范围的表达
