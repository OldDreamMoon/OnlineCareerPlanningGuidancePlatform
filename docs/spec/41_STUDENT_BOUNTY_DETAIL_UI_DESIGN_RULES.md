# 学生端企业实战任务详情页 UI 设计需求

> 文档状态：`evolving`
> 当前版本：2026-04-02
> 页面范围：学生端 `/bounty/:taskId`
> 文档用途：本文件是给“只负责生成前端样式模板、不了解项目上下文”的 AI 使用的自包含设计任务书。请基于本文件独立设计一个全新的宽屏桌面端任务详情页模板，不依赖项目内其他文件。

## 1. 你正在设计什么页面

这是学生查看单个企业实战任务详情，并决定是否提交成果的页面。

这个页面同时还承担一个重要作用：

- 如果学生已经提交过成果，这里还是他回看提交内容和企业审核结果的页面

一句话理解：

`这是“任务阅读 + 成果提交 + 结果回看”的合并工作台。`

## 2. 页面必须传达的业务语义

页面必须让学生明确理解以下事实：

- 这是一个真实任务，不是岗位投递页
- 学生要先看懂任务要求，再决定是否提交成果
- 当前平台内只支持一次提交
- 提交形式是真实的“成果说明 + 外部链接”
- 企业后续会在平台内给出结果说明
- 如果企业还要进一步沟通、安排面试或推进录用，默认发生在平台外

## 3. 页面真实支持什么

请把页面理解为当前已经能拿到以下信息：

### 3.1 任务基础信息

- 任务标题
- 企业名称
- 奖励说明
- 当前状态
- 截止时间
- 当前提交总数

### 3.2 任务正文结构

任务详情中可能包含这些结构化内容：

- 任务背景
- 希望解决的问题
- 需要提交什么
- 交付形式
- 最看重什么
- 适合方向
- 适合人群
- 参考资料
- 注意事项

这些内容是这个页面必须清晰表达出来的重点。

### 3.3 学生自己的提交信息

如果学生已经提交过，这个页面还会拿到：

- 我的提交状态
- 我的成果说明
- 我的外部链接
- 企业给出的结果说明
- 提交时间
- 审核时间

## 4. 这个页面明确不支持什么

不要把页面设计成以下产品：

- 项目管理面板
- 站内聊天页
- 多版本投稿系统
- 平台文件中心
- 面试排期页
- 录用进度页

也不要假装页面已经支持以下能力：

- 本地文件上传
- 平台内附件预览
- 上传 PDF / ZIP / 图片到平台
- 第二次补交或覆盖提交
- 草稿保存
- 企业和学生站内即时对话

如果模板里想表达“文档 / 设计稿 / 仓库 / 演示”四类成果，必须全部通过“站外链接”语义来表现，而不是设计成平台内上传系统。

## 5. 宽屏桌面端设计目标

详情页应该同时具备这三种感受：

- 可读
- 可行动
- 可回看

页面整体希望呈现为：

- 学生侧明亮工作台风格
- 有任务身份感
- 有明显的阅读主线
- 有明确的提交动作区

不希望它看起来像：

- 一整页字段回显
- 单纯的长文详情页
- 表单后台
- 招聘流程页

## 6. 页面正式结构

建议采用宽屏桌面端的三段式结构：

1. 顶部 Hero 任务摘要区
2. 左侧主阅读区
3. 右侧提交进度 / 提交动作侧栏

## 7. 顶部 Hero 区设计要求

Hero 区必须是页面的第一个视觉重心。

Hero 至少应包含：

- 返回任务列表按钮
  - 位置建议：放在 Hero 内下方，而不是放到页面外部
- 任务标题
- 企业名称
- 状态 Badge
- 奖励说明
- 截止时间
- 提交总数
- 适合方向 / 适合人群 chips
  - 如果信息存在就展示

Hero 的视觉目标：

- 让用户立即感受到这是一个真实任务工作页
- 让关键信息一眼可扫到
- 让人愿意继续往下读，而不是被一堆平级信息淹没

Hero 不应做成：

- 只有标题和一排平铺数据卡
- 纯说明文本头部
- 极像岗位详情页

## 8. 左侧主阅读区设计要求

左侧主阅读区是详情页最重要的阅读区域。

它必须帮助学生先读懂任务，再去提交。

### 8.1 内容组织顺序

推荐顺序如下：

1. 任务背景
2. 希望解决的问题
3. 需要提交什么
4. 交付形式
5. 最看重什么
6. 参考资料
7. 注意事项

### 8.2 设计重点

设计时要特别强化这三个区域：

- `需要提交什么`
- `交付形式`
- `最看重什么`

因为这三项直接决定学生怎么准备提交内容。

### 8.3 阅读区禁止做法

不要把上述所有内容都做成完全等权重的九宫格小卡片。

正确方向应该是：

- 有明显主次
- 有更强的阅读流
- 重要内容更大、更靠前、更易读
- 次级内容作为辅助区出现

### 8.4 参考资料表达

如果任务有参考资料，建议设计成可点击资源卡，而不是一段普通文本。

资源卡可以表现为：

- 参考文档
- 原型地址
- 业务说明
- 数据样例

但请记住：这些都只是“站外资源入口”，不是平台本地附件。

## 9. 右侧侧栏设计要求

右侧侧栏不是说明书区，而是“我的当前状态与动作区”。

整个右侧只围绕这两个问题：

- 我现在处于什么状态
- 我下一步能做什么

### 9.1 右侧应覆盖的真实状态

设计时必须至少覆盖以下五种状态：

1. 尚未提交，且任务开放中
2. 已提交待审核
3. 审核处理中
4. 继续接触
5. 未继续推进
6. 任务已关闭且我未提交

## 10. 未提交状态下的提交工作区

当学生还没提交，并且任务仍开放时，右侧应该是一个真正可操作的提交工作区。

必须包含：

- 当前状态提示
- 一段提交前说明
- 成果说明输入区
- 外部链接输入区
- 添加链接动作
- 提交按钮
- 一次性提交规则说明

### 10.1 成果说明输入区

“成果说明”必须是右侧最主要的输入区。

这个输入区不是随便填一句备注，而是企业审核时会优先阅读的正文。

请在设计中体现出它的重要性。

建议引导学生在这里说明：

1. 我完成了什么
2. 这些内容怎样对应任务要求
3. 企业应该优先看哪个部分
4. 还需要补充说明什么

### 10.2 外部链接输入区

外部链接输入区必须清楚告诉学生：

- 当前只能提交外部链接
- 不支持本地文件上传

建议把链接类型提示做得很直观，直接在 UI 中明确这些推荐类型：

- 说明文档
- 设计稿链接
- 代码仓库链接
- 演示视频 / 在线演示链接

可以通过以下方式表达：

- 四类资源小标签
- 输入框前的小图标
- 输入占位文案
- 提示卡片

### 10.3 一次性提交规则

页面必须明确表达：

- 当前同一任务只允许提交一次
- 提交后不能在页面内反复改版重投
- 所以在提交前应先把说明和链接整理清楚

这条规则建议放在右侧提交按钮附近。

## 11. 已提交状态下的回看区

当学生已经提交过，右侧必须切换成“只读进度与结果回看模式”。

至少应展示：

- 当前状态标签
- 我的成果说明
- 我的外部链接
- 企业结果说明
- 提交时间
- 审核时间

### 11.1 继续接触状态

如果企业给出的结果是继续推进，这个状态在 UI 中应表现为：

- 明显的积极状态，但不要做得像“已录用”
- 可以强调“继续接触”或“进一步交流”
- 若结果说明里出现明确意图，例如：
  - 继续沟通
  - 进一步交流
  - 邀请面试
  - 录用意向

则可以把这层意图做成高亮小标题或重点标签。

### 11.2 未继续推进状态

如果企业给出的结果是未继续推进，这个状态在 UI 中应表现为：

- 清晰但克制
- 更像结果反馈，不像惩罚或失败判定

结果说明中若出现类似文案，可以提炼成重点显示：

- 本次任务方向暂不完全匹配
- 当前提交完成度还可以继续加强
- 这次暂未继续推进，欢迎后续继续参与
- 感谢本次投入与提交

## 12. 详情页需要覆盖的典型页面状态

外部样式 AI 在出模板时，至少应准备以下典型状态：

### 12.1 状态 A：开放中，尚未提交

- 右侧为完整提交工作区

### 12.2 状态 B：开放中，已提交待审核

- 右侧展示我的提交与“等待审核”状态

### 12.3 状态 C：审核处理中

- 右侧展示“处理中”状态
- 结果说明区暂时为空或显示等待提示

### 12.4 状态 D：继续接触

- 右侧展示积极结果
- 结果说明更突出

### 12.5 状态 E：未继续推进

- 右侧展示结果说明
- 整体语气克制

### 12.6 状态 F：任务关闭且未提交

- 不再展示提交表单
- 展示“已关闭，不再接受新的成果提交”

## 13. 建议直接用于模板的示例任务内容

下面这组内容可以直接放进模板里，帮助外部 AI 设计真实的详情页。

### 示例任务基础信息

- 任务标题：用户流失预警专题分析与指标解释页
- 企业名称：北辰智联
- 奖励说明：1500 元奖金 + 优先实习沟通
- 当前状态：进行中
- 截止时间：2026-04-09 23:59
- 提交总数：2
- 适合方向：数据分析 / 产品经理
- 适合人群：应届生 / 有实习经验

### 示例任务正文

- 任务背景：
  - 我们正在推进一套面向运营团队的用户流失预警能力，希望把已有的数据指标重新组织成业务同学能快速读懂的说明页。
- 希望解决的问题：
  - 当前预警规则和指标说明过于技术化，运营与销售团队无法快速理解“为什么会预警、应该看哪些指标、不同风险等级代表什么”。
- 需要提交什么：
  - 一份流失预警说明页结构方案
  - 一版关键模块的页面草图或高保真稿
  - 一段不超过 500 字的指标解释逻辑说明
- 交付形式：
  - 在线说明文档
  - 设计稿链接
  - 如有能力可补充演示链接
- 最看重什么：
  - 是否真的把复杂指标讲清楚
  - 是否能体现业务阅读路径
  - 是否知道企业最关心的结论顺序
- 参考资料：
  - https://docs.example.com/churn-reference
- 注意事项：
  - 不需要做复杂数据建模
  - 请优先把信息层级和阅读路径整理清楚

## 14. 建议直接用于模板的提交内容示例

### 14.1 示例提交文案

我完成了一版“用户流失预警说明页”的信息结构方案，并补了一份高保真页面稿。整体思路是先用风险等级总览回答“谁最值得优先关注”，再用三组核心指标解释“为什么会被预警”，最后给出业务建议动作。建议企业优先查看设计稿首页和说明文档中的“指标解释顺序”部分。

## 15. 建议直接用于模板的结果说明示例

### 15.1 继续接触示例

继续接触意向：进一步交流  
补充说明：你的说明结构很清楚，特别是风险等级和指标解释的顺序处理得很好。希望你下周方便时，补充讲解一下你对业务动作区的设计思路。

### 15.2 未继续推进示例

未入选原因：当前提交完成度还可以继续加强  
补充说明：页面结构方向是对的，但对业务团队最关心的结论优先级还不够明确。欢迎后续继续参与更贴合的数据说明类任务。

## 16. 文案口径要求

页面文案请统一采用以下语气：

- 真实
- 克制
- 有产品感
- 不做过度营销

更适合使用的词：

- 任务详情
- 任务说明
- 交付要求
- 成果提交
- 我的提交进度
- 结果说明
- 继续接触

尽量少用的词：

- 立即投递
- 上传附件到平台
- 预约面试
- Offer 进度
- 候选人管理

## 17. 设计时必须遵守的限制

请在视觉表现上强化页面，但不要加入下面这些不存在的能力：

- 不要加入本地文件上传拖拽区
- 不要加入站内聊天窗口
- 不要加入任务评论区
- 不要加入版本历史时间线
- 不要加入面试预约模块
- 不要加入录用进展模块

如果需要增强页面层次，请通过以下方式实现：

- Hero 的身份感和主次结构
- 阅读区的主线组织
- 右侧侧栏的状态强化
- 结果说明的重点呈现
- 合理的卡片和资源表现

## 18. 交付要求

外部样式 AI 最终应交付一个完整的宽屏桌面端任务详情页模板，至少包含：

- 顶部 Hero 区
- 左侧主阅读区
- 右侧提交 / 回看侧栏
- 开放中未提交态
- 已提交态
- 继续接触态
- 未继续推进态
- 已关闭未提交态

请优先保证：

- 阅读层级强
- 提交动作清晰
- 结果回看清楚
- 看起来像一个真实的学生任务工作页，而不是单纯字段详情页
