## 1. 目标
- 把当前“最小联调可演示版”前端升级为“结构清晰、交互稳定、便于答辩演示”的正式版本。
- 在**不再大幅变更后端契约**的前提下，完成页面重构、状态统一、交互补齐与视觉一致性提升。
- 让后续开发按照清单逐项推进，减少返工与页面口径漂移。

## 1.1 当前执行优先级（2026-03-15 调整）
- 用户已明确要求进入“前端精细化 / 重构与美化设计”阶段，并优先从 B 端管理员侧开始推进。
- 本次调整**仅改变前端实施顺序**，不改变既有后端契约、角色边界与路由清单。
- 管理端本轮设计目标以“信息层次清楚、状态反馈明确、操作路径稳定”为主，不追求 C 端的艺术化视觉表达。
- 当前建议顺序调整为：`管理员后台基建 → 管理首页 → 内容治理 → 订单售后 → 支付对账 → AI 网关 → 用户管理 / 功能开关 → Landing / 公共首页 → 回到 C 端主链路`。

## 1.2 当前设计体系约束（2026-03-15 补充）
- 管理员后台继续使用 Ant Design 5 + ProComponents，保持后台工作台式信息密度与交互语义。
- C 端（Landing / 学生 / 导师 / 企业）统一使用 Tailwind CSS + Framer Motion 作为当前正式基线。
- shadcn/ui 作为 C 端后续组件沉淀方向，当前允许先按其风格约定自建组件，再逐步标准化。
- 两套设计体系必须显式做样式隔离，避免管理员全局 reset、颜色 token 或组件覆盖影响 C 端页面。
- `apps/web/templates/Landing Page.jsx` 仅作为 Landing 的视觉参考，不作为首页业务文案与模块信息的唯一依据。

## 1.3 当前适配边界（2026-03-20 补充）
- 当前毕业设计前端人工审查与修正阶段统一以宽屏桌面端为验收基线。
- 移动端 / 平板适配不作为本阶段阻塞项；如页面中已有移动端降级实现，可保留，但当前不纳入重点审查与修正范围。
- 若后续用户明确要求重新开启移动端适配，再把相关待办恢复为正式验收项。

## 3. 本轮前端正式重构的边界
### 3.1 本轮建议纳入
- Landing / 公共首页信息架构收口
- 页面结构重组
- 公共组件沉淀
- 数据请求与状态管理收敛
- 空态 / 错误态 / 加载态 / 成功反馈统一
- 演示路径所需的交互补齐
- 关键页面视觉一致性提升

### 3.2 本轮暂不优先
- 大规模重写为新 UI 框架
- 全站暗色主题 / 国际化 / 多端适配
- 复杂动画与重交互微动效
- 为了视觉效果而新增后端字段

## 4. 重构总原则
1. **先骨架后美化**：优先统一布局、导航、信息层级，再做视觉润色。
2. **先高频主链路后后台**：优先学生演示主链路，其次社区与导师，再到管理后台。
3. **一页一验收**：每个页面重构完都要能独立联调验证。
4. **不破坏现有闭环**：重构期间不牺牲已经跑通的业务流程。
5. **组件复用优先**：公共筛选条、状态卡片、详情页头部、列表空态尽量统一。
