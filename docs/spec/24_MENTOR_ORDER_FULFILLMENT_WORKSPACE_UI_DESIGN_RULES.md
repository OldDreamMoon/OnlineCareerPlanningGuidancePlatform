# 导师订单履约工作区 UI 设计规则

> 文档状态：`evolving`
> 最近同步：2026-04-08
> 适用范围：导师端 `/mentor/orders/:orderNo/workspace`
> 用途：以当前真实实现为准，定义导师单笔订单履约工作区的页面结构、数据边界与交互规则。

## 1. 页面定位

`/mentor/orders/:orderNo/workspace` 当前已经是导师处理单笔咨询订单的正式工作区。

它负责：

- 阅读单笔订单上下文
- 查看消息线程
- 生成 / 编辑 / 发送导师回复
- 查看必要的学生背景与材料摘要
- 查看评价、售后和时间线

它不负责：

- 多单搜索与分诊
- 财务分析
- 资料编辑

一句话：

`履约工作区负责把这一单处理清楚，不负责替导师管理全部订单。`

## 2. 当前真实实现（2026-04-08）

- 页面当前已正式接入：
  - `GET /api/v1/consult/orders/{orderNo}`
  - `GET /api/v1/consult/orders/{orderNo}/messages`
  - `POST /api/v1/consult/orders/{orderNo}/messages`
  - `GET /api/v1/consult/orders/{orderNo}/attachments`
  - `GET /api/v1/consult/orders/{orderNo}/attachments/{attachmentId}/content`
  - `POST /api/v1/consult/orders/{orderNo}/ai-reply-draft`
- 页面当前采用“本地工作区快照先渲染 + 后台静默回刷”的加载策略
- 初次进入页面时不应再自动滚到消息底部；当前只在新消息追加后再平滑滚动
- 顶部摘要区已收口为简洁的高优先级状态栏，不再使用复杂 Hero 样式
- 右侧上下文区当前只保留与当前回复直接相关的信息，已压掉与上方需求档案重复的长文本
- 右侧资料区已改为随页面自然撑高，不再采用独立长滚动盒

## 3. 当前真实契约与数据范围

### 3.1 单笔订单详情

当前详情已可提供：

- 订单号
- 当前状态
- 金额与支付方式
- 创建 / 支付 / 关闭时间
- 预约时间
- 导师回复截止时间
- 问题原文
- 结构化核心问题
- 预期结果
- 准备单摘要
- 材料摘要
- 评价信息
- 售后记录
- 学生背景摘要

### 3.2 消息线程

当前已可读取全部消息，并允许导师发送正式回复。

当前真实业务约束：

- 仅在 `PAID / ANSWERED` 状态允许继续发送
- 订单已关闭或已退款时只保留历史查看

### 3.3 附件链路

当前附件区已支持：

- 读取当前有效附件
- 预览
- 下载

### 3.4 AI 辅助回复

当前 AI 辅助回复已经是真实能力，不是静态占位：

- 前端调用 `POST /consult/orders/{orderNo}/ai-reply-draft`
- 草稿会基于订单上下文、准备单摘要与最近消息线程生成
- AI 只提供草稿辅助，不替代导师最终发送

## 4. 页面职责边界

### 4.1 履约区负责什么

- 单笔订单摘要
- 消息线程
- 正式回复输入区
- AI 草稿辅助
- 必要的上下文与材料
- 时间线
- 评价与售后摘要

### 4.2 履约区不负责什么

- 多单筛选
- 订单总览卡片
- 提现与账单
- 售后审批
- 导师资料修改

## 5. 当前页面结构

### 5.1 顶部状态栏

当前顶部区只保留高频必看信息：

- 返回订单中心
- 当前状态
- 回复截止时间
- 预约时间
- 风险标签
- 刷新

已经去掉与下方卡片重复的冗余信息，如单独的订单号卡片、创建时间卡片等重复块。

### 5.2 左侧沟通主区

当前左侧主区是页面主轴，包含：

- 学生咨询需求档案
- 消息线程
- 导师正式回复输入区
- AI 草稿辅助入口

### 5.3 右侧上下文区

当前右侧只保留当前回复必要信息：

- 订单基础信息
- 学生背景摘要
- 资料与附件
- 评价反馈
- 售后摘要
- 履约时间线

设计原则是：

- 只保留必要上下文
- 尽量去重
- 不堆叠与上方需求档案重复的长文本

## 6. 当前关键交互规则

### 6.1 回复发送

当前实现为：

- 先请求后端发送消息
- 后端成功后，前端立即把新消息写入本地状态和工作区快照
- 随后静默回刷服务端详情 / 消息 / 附件结果

因此：

- 已发送成功的消息即使后续刷新失败，也能先在当前页面看到
- 这不是绕过后端落库，而是“发送成功后的前端即时回显 + 后台对齐”

### 6.2 禁用态

当订单进入不可继续沟通状态时：

- 输入区进入只读或禁用态
- 页面必须给出明确产品文案说明

### 6.3 上下文卡片

- 右侧卡片当前应避免独立长滚动区
- 页面整体高度应随内容自然展开
- 左侧沟通区与右侧上下文区在桌面端应保持视觉平衡

## 7. 当前不再成立的旧口径

以下描述已经失效：

- “右侧资料区仍是待聚合占位”
- “履约区还没有学生背景摘要”
- “消息发送只需要后端成功即可，不需要页面快照即时回写”
- “顶部仍应维持复杂 Hero 风格摘要区”

## 8. 验收关注点

- 初次进入履约区时，页面不应自动滚到底部
- 顶部状态栏应清晰但简洁，不与下方卡片重复堆信息
- 导师发送消息后，应立即在当前页面看到新消息，并在后台完成静默回刷
- 右侧上下文区应只保留必要信息，不应再出现大量重复资料或独立长滚动盒
- AI 草稿生成、附件预览 / 下载与评价 / 售后摘要应稳定可见
