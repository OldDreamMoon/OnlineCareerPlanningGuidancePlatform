# AI 模拟面试页面样式设计规则

> 文档状态：`evolving`
> 最近整理：2026-04-16
> 适用对象：继续为 `/ai/interview` 做 UI 设计、视觉重构、交互提案的 AI / 设计协作者
> 当前实现参考：
> - `apps/web/src/pages/InterviewPracticePage.tsx`
> - `apps/web/src/lib/interviewLiveClient.ts`
> - `apps/web/templates/interview/prepare page.jsx`
> - `apps/web/templates/interview/chat page.jsx`
> - `apps/web/templates/interview/report page.jsx`

## 1. 文档目的

本文档不是逐像素实现规范，也不是前端代码任务单。

它的目标是：

- 向其他 AI 说明 AI 模拟面试页面当前的产品定位、设计边界与真实能力状态
- 帮助后续 UI 设计不要只停留在“做得更炫”，而是更贴近本项目的学生主链路
- 让新的视觉方案能够和学生工作台、简历优化页、技能星图页形成同一套 C 端设计语言

如果把这份文档交给其他 AI，期望它们输出的是更成熟的页面结构、卡片语言、排版层级与桌面端体验提案，而不是泛泛的“换色、加玻璃、加阴影”建议。

## 2. 产品定位

`/ai/interview` 不是一个独立的技术演示页，也不是纯聊天工具页。

它在整个项目中的定位是：

- 学生工作台主链路中的核心 AI 练习页
- “求职准备工作台”的一部分
- 从“准备材料”到“表达练习”再到“复盘改进”的连续闭环
- 服务于大学生求职准备，而不是面向开发者展示模型能力

一句话概括：

`它应该看起来像大学生求职准备过程中的高价值训练舱，而不是一个炫技式 AI 聊天窗。`

## 3. 当前真实功能边界

以下边界来自当前代码、tracking 与现阶段前端验收口径，后续设计默认以这里为准。

### 3.1 已稳定存在的能力

- 学生角色优先访问，非学生角色显示占位引导
- 单路由三阶段：
  - 准备页
  - 面试中
  - 复盘页
- `text / voice / live` 三模式
- 浏览器 `MediaRecorder` 录音提交
- `live` 会话页已具备 WS 状态、麦克风状态、播放状态、token 统计、实时字幕与事件日志
- 手动上传音频文件作为兜底
- 面试复盘展示：
  - 总分
  - 高光表现
  - 待提升区
  - 下一步建议
  - AI Meta
  - moderation

### 3.2 当前仍应诚实表达的边界

- `targetCompany` 当前主要是前端上下文展示，不应设计成“已深度参与后端定制面试”
- `difficulty` 当前主要作用于前端流程语义和气氛，不应设计成“AI 已显著切换面试策略”的强承诺
- Gemini Live 当前仍是测试模式：依赖独立 Python WebSocket bridge，不能包装成“正式生产级实时语音面试服务”
- 手动重连当前会保留页面 transcript，但 Gemini 侧会新开一个 Live 会话；不要在设计上暗示“已完整上下文续接”
- TTS 已用于文本/语音模式的追问与总结朗读，但它与 `live` 的实时模型语音不是同一条技术链路，不适合被包装成“全部模式都已统一稳定”
- 结构化雷达图不应被当成当前稳定主特性强展示
- `/skills -> /ai/interview` 的专项上下文仍未完全闭环，不要把技能定向面试包装成已完整打通的主卖点

### 3.2.1 已确认的后续设计方向（尚未实现）

- 若后续正式推进“技能节点专项 AI 测试”，不建议把它继续塞进当前通用 `/ai/interview` 准备页中，再靠隐藏控件来伪装成专项模式。
- 原因是当前通用面试页的产品定位、配置结构与 prompt 语义都明显偏向“岗位导向的求职模拟面试”。
- 更合理的做法是：在 AI 面试域下新增独立的 skills 专项入口与精简准备模式，同时在 AI gateway 中为专项测验配置独立 scene / prompt template。
- 即：它仍属于 AI 面试体系，但应作为独立场景模式存在，而不是现有通用准备页的一个薄开关。

### 3.3 设计表达原则

页面可以更高级、更完整，但不能让用户误以为：

- 所有参数都已经真实影响 AI 生成
- `live` 测试模式已经像正式生产产品一样稳定可用
- 所有语音播报能力都来自同一条成熟实时语音链路
- 技能上下文和专项验证已经完全接入

设计要有产品感，但要保持能力表达诚实。

### 3.4 本轮确认纳入的前端体验功能

以下功能已由当前会话确认，后续其他 AI 在做 `/ai/interview` UI 提案时，应默认把它们视为页面正式需求的一部分，而不是“可有可无的灵感点”。

这些功能当前优先从前端用户体验角度设计，不要求后端能力已经全部就绪。

#### 准备页侧

- 面试类型
- 面试官风格
- 本轮会带入哪些资料
- 回答辅助器（作为准备区设置的可选功能）
- 设备状态面板

#### 面试中侧

- 速记板
- 专注模式
- 键盘快捷操作
- 录音预听与重录

#### 复盘页侧

- 报告导出

#### 设计落地原则

- 这些功能可以先用前端本地状态、假数据或展示型交互实现体验验证
- 页面设计时应预留这些功能的清晰位置，不要等后端完成后再“硬塞入口”
- 新功能的加入不能破坏三阶段主叙事：准备、面试中、复盘
- 新功能应优先增强“训练舱”体验，而不是增加参数堆叠和操作负担

## 4. 当前阶段验收口径

当前前端人工审查与修正阶段统一以宽屏桌面端为验收基线。

因此后续 AI 给出的设计方案，应默认：

- 优先考虑桌面端宽屏体验
- 不把移动端适配作为当前核心目标
- 不为了兼容小屏而牺牲桌面端的层次感、沉浸感和信息组织质量

建议默认桌面端按以下尺度思考：

- 顶栏与主容器宽度与学生工作台基线对齐
- 主容器使用更宽的工作区尺度，而不是传统表单页的窄列中心布局
- 聊天区、右侧辅助区、复盘区都应基于宽屏桌面端做主构图

## 5. 与学生工作台的关系

AI 面试页属于学生端 C 端体系，不能做成与学生工作台完全割裂的另一个产品。

必须保留的连续性：

- 顶栏样式要与学生工作台同一视觉系统
- 主容器宽度、边距节奏、卡片圆角和按钮语言应与工作台同源
- 顶层品牌感要一致：它是“AI Career 学生工作台”的子场景，而不是外链工具
- 页面应当让用户感到自己仍在同一个成长系统里

但它也不应该完全复制工作台首页。

允许出现的差异化：

- 更聚焦训练任务
- 更高的信息沉浸度
- 更明显的过程感和反馈感
- 更强的对话主舞台

一句话：

`它应该是学生工作台里的训练舱，而不是另起一套视觉宇宙。`

## 6. 整体设计关键词

后续 AI 若要继续给 UI 提案，建议围绕以下关键词展开：

- 大学生求职训练舱
- 准备感，而不是考试恐吓感
- 产品化，而不是技术演示感
- 真实、克制、可信
- 高圆角、轻玻璃、浅色工作区
- 局部深色舞台作为强调，而不是全页深黑
- 以中文为主
- 信息层级清楚
- 有情绪支持，但不过度幼态化
- 有科技感，但不赛博朋克

不建议的关键词：

- 黑客终端
- 极客控制台
- 军事指挥舱
- 纯大模型实验台
- 赛博霓虹聊天室
- 夸张游戏化战绩页

## 7. 页面应有的叙事结构

AI 面试页的叙事不应是“填参数 -> 开始聊天 -> 看结果”这么机械。

更推荐的叙事路径是：

1. 我是谁，我正在准备什么岗位
2. 我为什么要练这一轮
3. 我选择什么方式开始
4. 我如何在练习中获得即时反馈
5. 这一轮结束后，我应该怎么继续推进下一步

因此页面设计要同时承载：

- 训练前的准备感
- 训练中的专注感
- 训练后的复盘感

## 8. 三阶段页面设计规则

### 8.1 准备页

准备页的角色不是“参数面板”，而是“训练前整理台”。

应该强调：

- 这轮练习服务于什么目标岗位
- 页面已经带入了哪些学生画像信息
- 用户可以怎么开始最稳妥
- 当前语音能力有哪些边界

布局建议：

- 左侧更像“准备引导 + 训练价值说明”
- 右侧才是“参数设置 + 麦克风检测 + 开始按钮”
- 第一屏就要让人明白：这是一轮有上下文的模拟面试，而不是空白聊天输入框

准备页推荐保留的元素：

- 一句更像教练的主标题
- 动态但克制的鼓励语
- 学生画像摘要
- 面试类型选择
- 面试官风格选择
- 本轮会带入哪些资料
- 模式选择卡
- 回答辅助器开关
- 设备状态面板
- 麦克风准备状态
- 明确的开始按钮

准备页新增功能要求：

- `面试类型`
  - 应作为准备页一级功能出现
  - 建议以卡片组或 segmented control 呈现，而不是下拉框
  - 选项文案应面向学生求职场景，例如：
    - 自我介绍
    - 项目深挖
    - 八股基础
    - 行为面试
    - 压力追问
- `面试官风格`
  - 应作为训练气氛设定，而不是隐藏高级设置
  - 建议以 2 到 4 个清晰角色卡呈现，例如：
    - 温和引导型
    - 常规校招型
    - 高压追问型
    - HR 沟通型
  - 风格卡应兼顾文字语气与视觉语气，不要只改标签名
- `本轮会带入哪些资料`
  - 应让用户明确知道这一轮练习会参考哪些信息
  - 建议以可勾选胶囊、资料抽屉或预览卡形式展示
  - 可带入项可包括：
    - 目标岗位
    - 自我介绍
    - 项目经历
    - 技能标签
    - 简历摘要
  - 即使后端暂未全部使用，也要让用户形成“训练前整理资料”的体验
- `回答辅助器`
  - 作为准备区的可选功能开关，而不是面试中突然出现的打断项
  - 开启后，可以在面试中提供弱提示，例如：
    - STAR 结构提醒
    - 量化结果提醒
    - 回答完整度提醒
  - 在准备页应明确告诉用户：这是辅助作答，不是自动生成答案
- `设备状态面板`
  - 设备状态不应只是一句权限提示
  - 建议整合为一个更完整的小面板，包含：
    - 麦克风权限状态
    - 浏览器兼容状态
    - 推荐输入方式
    - 是否建议使用耳机
    - 录音格式提示
  - 若未来支持更多检测项，也应在这里扩展，而不是散落到多个提示条里

准备页不建议：

- 把参数区做得像后台配置页
- 同时堆太多实验性参数
- 用大量英文标签破坏中文主叙事
- 把“难度、企业、语音”做成比“目标岗位”还抢眼的区域

### 8.2 面试中

面试中的核心是“对话主舞台”。

这一阶段最重要的视觉原则：

- 对话区必须是绝对主角
- 右侧状态区是辅助，不应与聊天区抢主舞台
- 输入区与录音区要让人一眼知道下一步动作
- 页面要有过程推进感，但不要像监控系统

布局建议：

- 左侧大面积对话区
- 右侧较窄但信息密度高的状态辅助栏
- 输入区固定在下方，并保持操作清晰

对话区设计要求：

- AI / 用户 / 系统状态要明显区分
- 气泡层级要清楚，但不能做成社交 IM 风格过重
- AI 追问需要有“面试官”感，不要像普通客服
- 用户回答气泡要稳定、清晰、可快速回看
- “生成中 / 转写中 / 提交中”状态需要明确但克制

右侧辅助栏应突出：

- 当前轮次进度
- 当前模式
- 即时点评
- 画像上下文
- 当前能力边界提示
- 回答辅助器状态
- 速记板入口或常驻区块

右侧辅助栏不应：

- 堆过多花哨数据仪表盘
- 制造“分数实时波动”的焦虑型交互
- 比对话区更抢视觉中心

面试中新增功能要求：

- `速记板`
  - 应作为面试中核心辅助能力之一
  - 位置建议：
    - 右侧辅助栏中的独立卡片
    - 或专注模式外的可展开侧板
  - 速记板更适合记录：
    - 项目关键词
    - 指标数字
    - 回答提纲
    - 下轮要补充的点
  - 速记板不应像完整文档编辑器，应保持轻量、快速、无干扰
- `专注模式`
  - 应提供一个让用户“只看问题与回答”的模式
  - 开启后建议弱化或折叠：
    - 右侧辅助栏
    - 非必要提示卡
    - 次级状态信息
  - 专注模式下应保留：
    - 当前问题
    - 输入区 / 录音区
    - 最核心的进度与退出入口
- `键盘快捷操作`
  - 桌面端设计应默认支持快捷键思路
  - 至少应为以下操作预留入口说明与视觉提示：
    - Enter 发送
    - Shift + Enter 换行
    - 开始录音 / 停止录音
    - 打开或关闭速记板
    - 打开或关闭专注模式
  - 快捷键说明可通过帮助浮层、提示抽屉或输入区轻提示呈现
- `录音预听与重录`
  - 录音结束后不应只提供“直接提交”
  - 应有一个“录音结果确认层”
  - 至少应支持：
    - 预听录音
    - 删除本次录音
    - 重新录制
    - 确认后提交
  - 这一层的交互应当清楚、轻量，避免让用户误以为录音已自动上传成功

### 8.3 复盘页

复盘页不应只是“结果展示页”，而应更像“训练总结 + 下一步行动建议页”。

必须突出：

- 总分
- 高光点
- 问题点
- 下一步建议
- 再练一轮 / 去看简历优化等后续动作

复盘页的正确气质：

- 可信
- 清晰
- 有方向感
- 有成长反馈

复盘页不建议：

- 做成花哨战报
- 过度游戏化
- 用复杂雷达图挤占真正重要的文字建议
- 把 AI Meta / moderation 做成比用户成长建议更重要的内容

复盘页新增功能要求：

- `报告导出`
  - 应被视为复盘页正式动作之一，而不是边缘功能
  - 导出目标是让用户能够保存、回看、展示本轮训练结果
  - 设计上建议放在复盘页顶部操作区或结尾 CTA 区
  - 导出形式可以先按前端体验预留：
    - 导出报告卡片
    - 导出长图
    - 导出 PDF
    - 复制摘要
  - 即使当前只做前端假导出或视觉预留，也应保证操作入口足够清晰

## 9. 视觉语言规则

### 9.1 色彩

推荐方向：

- 浅底工作区为主
- `indigo / teal / sky / emerald` 作为主强调色
- 少量 `amber / rose` 用于提醒与风险提示
- 深色块仅用于重要聚焦卡或强调舞台

不推荐方向：

- 全页深黑底
- 高饱和霓虹紫主导
- 大面积荧光撞色
- 红色高压氛围主导整页

### 9.2 材质

推荐方向：

- 高圆角卡片
- 白色或浅色半透明卡片
- 轻模糊背景
- 柔和阴影
- 局部深色主舞台卡

不推荐方向：

- 纯扁平后台盒子
- 太重的拟物金属质感
- 过度发光边框
- 机械控制台式网格密集背景

### 9.3 排版

推荐方向：

- 中文主导
- 大标题明确
- 二级标题清楚
- 标签与状态语使用小字号大写或半大写时要克制
- 正文行高偏舒展

不推荐方向：

- 到处都是英文 section 名
- 大量缩写化技术语
- 标签字密度过高
- 同一屏里出现太多标题层级

### 9.4 图标

图标应承担“识别信息类型”的作用，而不是“装饰密度”。

推荐：

- 每个卡片一个主图标
- 同类状态用一致图标系统
- 保持线性图标和简洁图标风格统一

不推荐：

- 同一屏里图标尺寸、风格差异过大
- 每个胶囊、每句提示都塞图标
- 把图标做成主要视觉主角

## 10. 动效规则

AI 面试页需要动效，但动效服务于“过程反馈”，不服务于“炫”。

应保留的动效类型：

- 准备页鼓励语切换
- 卡片轻微入场
- 对话消息进入
- AI 生成中的轻量加载提示
- 录音中的波形或节奏反馈
- 复盘页分数或摘要渐进展示

应克制的动效类型：

- 大面积背景持续漂浮
- 高频闪烁
- 夸张弹跳
- 会干扰输入与阅读的循环动画

一句话：

`动效要像陪练反馈，不要像舞台表演。`

## 11. 组件级设计规则

### 11.1 顶栏

- 与学生工作台同一壳层基线
- 左侧是品牌与返回关系
- 中间或右侧才是阶段状态
- 用户身份胶囊与主操作按钮保持一致语言

### 11.2 按钮

- 主按钮：渐变或品牌强调色，负责“开始 / 提交 / 再练一轮”
- 次按钮：白底描边，负责“返回 / 切换 / 重置”
- 危险按钮：仅在“结束当前练习 / 取消录音”这类场景使用

### 11.3 状态胶囊

- 只用于表达当前阶段、模式、模块状态
- 颜色语义稳定：
  - 绿色：可用 / 成功
  - 琥珀：占位 / 警告 / 边界
  - 靛蓝：处理中 / 当前聚焦
  - 灰色：普通说明

### 11.4 对话气泡

- 用户气泡与 AI 气泡必须一眼区分
- AI 气泡要更稳重、专业
- 用户气泡可以更有行动感
- 不要做成社交聊天 app 的娱乐化气泡

### 11.5 结果卡

- 结果卡要优先强调文字结论
- 分数是入口，不是结论本身
- 高光、问题、建议的结构要稳定统一

## 12. 文案与语气规则

页面文案需要保持以下语气：

- 友好
- 陪练型
- 不羞辱用户
- 不制造过强焦虑
- 不把 AI 说成绝对权威

更适合的表达：

- 这轮可以从这里开始
- 先把表达结构讲清楚
- 当前这项能力还在接入中
- 可以先用文字模式完成一轮
- 这轮报告已经够你继续精修

不适合的表达：

- 全真高压审判
- 立即挑战你的极限
- 面试失败预警
- 智能裁决你的水平

## 13. 明确禁止方向

如果其他 AI 给新方案，请默认不要：

- 把页面改成纯深色终端或黑客控制台
- 把页面改成社交聊天 app 风格
- 把学生、导师、企业重新做成并列入口
- 把 `live`、TTS、技能上下文包装成已经全部成熟的能力
- 为了炫技加入大量无意义仪表盘
- 用英文主导页面表达
- 用过强游戏化战报代替真实复盘建议
- 让右侧辅助面板比对话区更抢眼
- 让页面看起来像“模型参数调试台”

## 14. 希望其他 AI 重点给出的内容

如果把本页继续交给其他 AI 设计，最希望它们给出的不是抽象灵感，而是以下内容：

- 一套更成熟的三阶段页面整体构图
- 准备页如何更像“训练前整理台”而不是参数表单
- 面试中页面如何进一步强化“对话主舞台 + 辅助侧栏”
- 复盘页如何更像“成长总结页”，而不是单纯战报
- 如何把面试类型、面试官风格、资料带入、回答辅助器自然纳入准备页
- 如何把速记板、专注模式、快捷键、录音预听与重录自然纳入面试中页面
- 如何把报告导出做成复盘页的正式动作，而不是附属按钮
- 更统一的卡片语言、边框、圆角、阴影、色彩节奏
- 更成熟的中文标题、标签与卡片排版体系
- 哪些英文小标签应删减，哪些可以保留
- 哪些动效该保留，哪些动效应当更克制

## 15. 可直接交给其他 AI 的任务描述

可以直接把下面这段交给其他 AI：

```text
请为一个“大学生求职准备工作台”中的 AI 模拟面试页面做桌面端 UI 设计提案。页面属于学生工作台的子场景，不是独立工具站，也不是极客控制台。

页面必须围绕三阶段组织：
1. 准备页：训练前整理台
2. 面试中：对话主舞台
3. 复盘页：成长总结与下一步建议

并且默认把以下前端体验功能纳入正式需求：
- 准备页：面试类型、面试官风格、本轮会带入哪些资料、回答辅助器开关、设备状态面板
- 面试中：速记板、专注模式、键盘快捷操作、录音预听与重录
- 复盘页：报告导出

设计目标：
- 中文主导
- 产品化、可信、克制
- 有科技感，但不赛博朋克
- 与学生工作台属于同一设计系统
- 浅底、高圆角、轻玻璃、品牌渐变点缀
- 宽屏桌面端优先

必须诚实表达当前能力边界：
- targetCompany / difficulty 目前不应被包装成深度影响 AI 的成熟能力
- `live` 与 TTS 都不应被包装成当前稳定核心卖点
- 技能上下文注入还不是完整闭环

请重点输出：
- 页面整体构图
- 三阶段各自的层级与卡片语言
- 上述新增功能分别应放在页面哪里、以什么交互形态出现
- 顶栏、主舞台、辅助侧栏、输入区、复盘卡的设计规则
- 推荐色板、材质、排版、动效策略
- 不要给泛泛而谈的建议，要给具体的视觉方向与结构方案
```

## 16. 一句话总结

`AI 模拟面试页应该被设计成学生工作台中的“求职训练舱”：它有准备感、过程感和复盘感，产品化、可信、克制，强调成长反馈，而不是炫技式 AI 聊天。`
