# 导师工作台 UI 设计规则

> 文档状态：`evolving`
> 最近同步：2026-04-08
> 适用范围：导师端 `/mentor/dashboard`
> 用途：作为导师工作台当前真实实现的说明文档，并为后续 UI 收口提供稳定边界。

## 1. 页面定位

`/mentor/dashboard` 当前已经是导师登录后的正式首页，不再是过渡占位页。

它的职责是：

- 帮导师快速判断“现在先处理什么”
- 汇总认证、接单、排期与近期订单的关键状态
- 把导师送到资料页、订单中心、履约区和财务中心等真实工作页

它不负责：

- 完整资料编辑
- 完整排期编辑
- 单笔订单的深度沟通
- 财务明细与提现处理

一句话：

`导师工作台是分诊台，不是编辑台，也不是经营大屏。`

## 2. 当前真实实现（2026-04-08）

- `/dashboard` 当前只负责按角色分流；导师登录后的真实落点是 `/mentor/dashboard`
- 页面真实数据由以下接口组合而成：
  - `GET /mentor/dashboard`
  - `GET /mentor/profile`
  - `GET /certification/me`
  - `GET /mentor/schedule/slots/me`
- 前端当前采用“旧快照先渲染 + 后台静默刷新”的工作台模式，避免每次进入都从空白态重新加载
- 顶栏已统一复用导师工作台壳层，不再保留旧的页内锚点式占位导航
- Hero、快捷入口和待处理订单卡片均已接到真实业务页，不再跳回占位页或无效路由
- 最近订单区的主动作直接进入 `/mentor/orders/:orderNo/workspace`
- 右侧区域已收口为单张“服务状态摘要”卡，不再保留旧的“名片概览 + 独立认证卡 + 额外占位说明”的拆分结构

## 3. 当前可直接复用的真实数据

### 3.1 `GET /mentor/dashboard`

当前已稳定返回：

- `pendingPaidCount`
- `answeredCount`
- `closedCount`
- `totalRevenueFen`
- `totalOrders`
- `avgRating`
- `recentOrders`

这些字段足够支撑：

- 待处理订单提示
- 已答复待确认数量
- 已完成订单与累计评分摘要
- 最近订单入口

### 3.2 `GET /mentor/profile`

当前工作台实际消费的导师资料摘要包括：

- `displayName`
- `avatarUrl`
- `realName`
- `showRealName`
- `companyName`
- `jobTitle`
- `expertiseTags`
- `serviceScenes`
- `packages`
- `replyRhythm`
- `prepMaterials`
- `available`
- `approvalStatus`

这里的作用是给工作台提供只读服务状态摘要，不承担编辑。

### 3.3 `GET /certification/me`

当前用于首页判断：

- 当前认证状态 `approvalStatus`
- 当前有效提交 `currentSubmission`
- 审核备注 `reviewNote`

工作台只展示“当前状态 + 下一步动作”，不展开完整材料管理。

### 3.4 `GET /mentor/schedule/slots/me`

当前已可支撑：

- 今日已预约数量
- 未来 7 天可预约时段数量
- 最近一条预约 / 最近一条空档
- 排期健康度提醒

首页只做摘要，不做排期编辑器。

## 4. 页面职责边界

### 4.1 工作台负责什么

- Hero 状态判断与主 CTA
- 待处理订单分诊
- 排期健康度摘要
- 认证状态摘要
- 服务状态摘要
- 快捷入口

### 4.2 工作台不负责什么

- 头像上传
- 套餐编辑
- 认证提交流程主表单
- 批量创建 / 批量清空排期
- 账单列表与提现流转
- 单笔订单消息线程

## 5. 当前页面结构

### 5.1 Hero

Hero 当前围绕三类真实状态动态生成文案和动作：

- 认证是否通过
- 当前是否开启接单
- 近期排期是否健康

当前主动作只会跳向真实页面：

- `/mentor/orders`
- `/mentor/profile?tab=schedule`
- `/mentor/profile?tab=certification`
- `/mentor/finance`

### 5.2 待处理订单区

首页订单区当前只承接“分诊级摘要”：

- 最近订单
- 待回复订单
- 已答复待确认订单

卡片动作只保留：

- 查看订单中心
- 直接进入履约区

不在首页直接展开完整消息线程。

### 5.3 排期健康度

该区当前展示：

- 今日已预约
- 本周可预约时段
- 最近预约 / 空档
- 排期健康判断

主动作当前固定回到 `/mentor/profile?tab=schedule`。

### 5.4 认证状态摘要

该区只负责说明：

- 当前是否已通过
- 是否需要补件
- 是否影响名片公开与接单

主动作当前固定回到 `/mentor/profile?tab=certification`。

### 5.5 服务状态摘要

右侧当前已收口为单卡，重点展示：

- 当前接单状态
- 套餐与起步价摘要
- 服务场景 / 擅长方向
- 回复节奏与准备材料摘要

这里强调的是“当前对外服务状态”，不是资料页的缩小版表单。

## 6. 交互与实现规则

- 首页默认优先展示已有快照，再静默刷新真实数据；不要求前台弹出显式“缓存已更新”提示
- 手动刷新仅作为辅助动作，不能成为页面可用的前提
- 首页所有 CTA 都必须跳向真实工作页，不能再回到旧占位页或无效锚点
- 首页摘要文案应保持产品化表达，不保留“待聚合”“真实接口待接入”之类开发态文案
- 若某项数据当前为空，应给出正常空态，不把空态包装成能力缺失提示

## 7. 当前不应再写进文档的旧口径

以下表述已经不符合当前实现，后续文档不得继续使用：

- “导师工作台仍是占位页”
- “首页仍主要是页内锚点跳转”
- “右侧仍按名片概览 / 认证进度 / 占位说明多卡拆分”
- “工作台尚未接通跨页联动”

## 8. 验收关注点

- 登录导师账号后访问 `/dashboard`，应自动进入 `/mentor/dashboard`
- 工作台首屏应能稳定展示旧快照，并在后台完成静默刷新
- Hero 与快捷入口应稳定跳转到 `/mentor/orders`、`/mentor/profile`、`/mentor/finance`、`/community`、`/notifications`
- 最近订单卡的“进入履约区”应稳定跳转 `/mentor/orders/:orderNo/workspace`
- 首页不应出现完整编辑表单、完整账单列表或单笔订单聊天区
